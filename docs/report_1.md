## 1. Выбор модели и контекста применения

**Модель**: SmolVLA (Small Vision-Language-Action)  
**Задача**: Мультимодальное управление роботом (Vision + Language + Robot State → Actions).  
**Область применения**: Робототехника, манипуляция объектами.  
**Сценарий использования**: Инференс в реальном времени на бортовых вычислителях роботизированных платформ.  
**Требования**: Низкая задержка (latency < 100ms) для обеспечения стабильного управления и высокая энергоэффективность.

---

## 2. Целевая аппаратная платформа

Для разработки и тестирования используется следующая конфигурация:

*   **ОС**: Windows 10
*   **CPU**: AMD Ryzen 7 5800H (8 ядер, 16 потоков)
*   **GPU**: NVIDIA GeForce RTX 3060 Laptop GPU (6 GB VRAM)
*   **RAM**: 16 GB DDR4
*   **Software Stack**: Python 3.10, PyTorch 2.7.1+cu126, LeRobot 0.4.3

**Ограничения платформы**:
*   **6 GB VRAM**: Ограничивает возможность использования больших батчей при обучении Teacher-модели.
*   **Thermal Throttling**: Мобильная версия GPU может снижать частоты при длительной нагрузке.

---

## 3. Архитектура модели

Модель SmolVLA базируется на архитектуре SmolVLM и адаптирована для задач управления:

*   **Vision Encoder**: Обработка визуальных данных с камер (обычно 2 камеры).
*   **VLM Backbone**: 16 слоев трансформера (согласно конфигурации проекта).
*   **Action Head**: MLP для предсказания векторов действий (7-dim для задач типа PushT/Libero).
*   **Параметры**: ~450.05 млн.
*   **Размер (FP32)**: ~1716.79 MB.

---

## 4. Вычислительные затраты и узкие места (Bottlenecks)

На основе анализа архитектуры и предварительного профилирования выявлены следующие узкие места:

1.  **Backbone Transformer (16 слоев)**: Основной источник вычислительной сложности. Операции Attention имеют квадратичную сложность от длины последовательности.
2.  **Vision Encoder**: Высокая нагрузка при обработке нескольких видеопотоков высокого разрешения.
3.  **Memory Bandwidth**: Большой размер модели (1.7 ГБ) замедляет инференс из-за необходимости перекачки весов, особенно на Edge-устройствах с общей памятью.

## 6. Гипотезы по ускорению

1.  **Knowledge Distillation (KD)**: Создание "Student" модели с меньшим количеством слоев (8 вместо 16) и скрытой размерностью.
2.  **Structured Pruning**: Удаление до 30% наименее важных весов в полносвязных слоях.
3.  **INT8 Quantization**: Снижение точности весов с FP32/FP16 до INT8 для ускорения вычислений на Tensor Cores.
4.  **Mixed Precision (FP16)**: Использование половинной точности для инференса без потери качества.

---

## 7. Инженерные компромиссы

*   **Сжатие vs Точность**: Агрессивная дистилляция (ratio=0.5) может привести к потере точности управления в сложных сценариях.
*   **Квантование**: INT8 значительно ускоряет инференс, но требует калибровки на представительном наборе данных, чтобы избежать деградации.
*   **Pruning**: Структурный прунинг эффективнее для GPU, но требует дообучения (fine-tuning) для восстановления точности.

## 9. Инженерные выводы

Baseline модель SmolVLA (450M параметров) является слишком тяжелой для real-time инференса на бюджетных Edge-платформах. Необходимо применение дистилляции для уменьшения количества слоев трансформера минимум в 2 раза. Предварительные тесты показывают, что Student-модель с ratio=0.5 имеет всего ~1 млн обучаемых параметров в Action Head и проекционных слоях, что при сохранении весов предобученного энкодера дает значительный потенциал для оптимизации.
