# ADR-0004: Wave-based backend migration order and temporary facades

- Статус: Accepted
- Дата: 2026-05-08

## Контекст

Нужен управляемый порядок миграции модулей backend по слоям с минимизацией рисков регрессии, контролем импортов на переходном этапе и сохранением стабильных API для внешних клиентов.

## Решение

### 1) Порядок волн

- Wave 1 (низкий риск): `files`, `profile`, `analytics`
- Wave 2: `jobs`
- Wave 3 (высокий риск): `agents`, `chat`

### 2) Порядок работ внутри каждой волны

1. Перенос интерфейсов, доменных сервисов и use-case в `application`.
2. Перенос и адаптация интеграций в `infrastructure`.
3. Обновление `presentation`-слоя, роутеров и точек входа.
4. Включение feature-флагов для переключения между legacy и новым контуром.

### 3) Совместимость на переходе

До полного перевода call-sites сохраняются:

- временные фасады,
- deprecated-импорты,
- совместимые точки импорта с перенаправлением на новые модули,
- контракты DTO и схемы сериализации без breaking-изменений.

Удаление фасадов и deprecated-импортов выполняется только после подтверждения отсутствия внешних обращений, миграции всех внутренних импортов и прохождения тестов.

### 4) Контроль качества после каждой волны

После завершения каждой волны обязательно:

- обновить и запустить профильные тесты в `backend/tests/`,
- обновить архитектурные правила и карту слоёв в `docs/architecture.md`,
- зафиксировать изменения отдельным ADR (если изменены границы слоёв или контракт миграции),
- снять метрики (ошибки, latency, загрузка очередей) до/после переключения feature-флагов.

### 5) Критерии готовности волны

Волна считается завершённой только при выполнении всех условий:

- отсутствуют импорты из legacy-слоя в новые модули волны,
- все endpoint и фоновые задачи модуля работают через новый application-слой,
- пройдены unit/integration/smoke тесты,
- задокументированы временные фасады и срок их удаления.

## Последствия

- Снижены риски регрессии за счёт поэтапной доставки.
- Улучшена трассируемость архитектурных решений.
- Зафиксированы единые требования по совместимости импортов в переходный период.
- Добавлены измеримые критерии завершения каждой волны и контроль эксплуатационных метрик.
