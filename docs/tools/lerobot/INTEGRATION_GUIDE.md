# LeRobot — Руководство по интеграции с AgentsSwarm

## Общее описание

LeRobot — открытая платформа от HuggingFace для робототехнического AI. Она предоставляет полный стек инструментов для обучения, дообучения и развёртывания политик управления роботами: от сбора данных телеоперацией до асинхронного inference на реальном оборудовании.

В контексте AgentsSwarm LeRobot выступает **фундаментом для SmolVLA-компонента** — модели, ответственной за генерацию физических действий роботов. Ниже описано, как каждый модуль LeRobot применяется в архитектуре платформы.

---

## 1. SmolVLA — базовая VLA-модель

### Роль в AgentsSwarm

SmolVLA (`lerobot/smolvla_base`, 450M параметров) — основная политика генерации действий для роботов в рое. Модель принимает изображения с камер, сенсомоторное состояние робота и текстовую инструкцию, и генерирует chunk (последовательность) физических действий.

### Ключевые характеристики из LeRobot

- **Предобученная модель**: `lerobot/smolvla_base` доступна на HuggingFace Hub, обладает базовыми навыками манипуляции
- **Multiple camera views**: поддержка нескольких камер одновременно (фронтальная, боковая, запястная)
- **Сенсомоторное состояние**: помимо изображений модель получает текущее состояние суставов робота
- **Дообучение**: через CLI `lerobot-train` с минимальной конфигурацией
- **Inference**: через CLI `lerobot-record` для реального робота или через Python API

### Применение в AgentsSwarm

- **Cloud SmolVLA**: развёрнута на GPU-кластере (A100), обслуживает запросы от Orchestrator, генерирует сложные последовательности манипуляции
- **Edge SmolVLA**: развёрнута на бортовом GPU робота (Jetson), обеспечивает реактивное управление с минимальной задержкой
- **Дообучение под задачи платформы**: каждый тип робота в рое дообучается на своих демонстрациях

## 2. X-VLA — кросс-платформенная VLA-модель

### Роль в AgentsSwarm

X-VLA (`lerobot/xvla-base`, 0.9B параметров) — более мощная альтернатива SmolVLA для сценариев с гетерогенным роем (разные типы роботов с разными морфологиями). Главная инновация — **Soft Prompts**: обучаемые эмбеддинги, кодирующие специфику конкретного робота и конфигурации камер.

### Ключевые возможности

- **Soft Prompts**: вместо отдельной модели для каждого типа робота используются наборы обучаемых эмбеддингов (Soft Prompts). Каждый тип робота в рое получает свой набор, при этом основная модель (backbone) остаётся общей
- **Cross-embodiment**: одна модель работает с разными морфологиями роботов — одноручными манипуляторами, бимануальными системами, мобильными роботами
- **Action Modes**: система реестра Action Modes адаптирует выход модели к пространству действий конкретного робота. Режим `auto` автоматически определяет размерность по датасету
- **Domain IDs**: до 30 уникальных конфигураций «робот + камеры». Каждому домену соответствует свой набор Soft Prompts
- **Адаптация Phase II**: новый робот адаптируется за счёт обучения только Soft Prompts (1% параметров, ~9M) при замороженном backbone — ~300× меньше обучаемых параметров, чем полное дообучение

### Применение в AgentsSwarm

- **Гетерогенный рой**: если в рое роботы разных типов (манипуляторы, мобильные платформы, бимануальные), X-VLA — предпочтительный выбор. Одна модель обслуживает все типы через разные Domain ID
- **Быстрая адаптация новых роботов**: при добавлении в рой нового типа робота достаточно обучить набор Soft Prompts (~3000 шагов), не переобучая всю модель
- **Custom Action Modes**: для нестандартных роботов AgentsSwarm можно зарегистрировать собственный Action Mode с кастомной функцией потерь, пре- и пост-процессингом

## 3. Асинхронный Inference

### Архитектура PolicyServer / RobotClient

LeRobot предоставляет готовую инфраструктуру асинхронного inference, критически важную для AgentsSwarm:

- **PolicyServer**: серверный процесс, выполняющий inference модели (SmolVLA, X-VLA, ACT и др.) на мощном GPU. Инициализируется пустым и конфигурируется при первом подключении клиента
- **RobotClient**: клиентский процесс на стороне робота, стримящий наблюдения на сервер и получающий action chunks. Работает по сети или локально

### Преимущество для AgentsSwarm

Синхронный inference вызывает **простои робота** (idle frames) — робот ждёт ответа модели. В рое роботов это критично: каждый простой — потеря эффективности. Асинхронный inference **устраняет простои полностью**: следующий chunk действий вычисляется до того, как текущий исчерпан.

### Ключевые параметры настройки

| Параметр | Рекомендация для AgentsSwarm | Описание |
|----------|------------------------------|----------|
| `actions_per_chunk` | 10–50 | Число действий в chunk. Больше — меньше вероятность пустой очереди, но ниже точность |
| `chunk_size_threshold` | 0.5–0.6 | Порог заполненности очереди для запроса нового chunk. 0.5 = запрос при 50% оставшихся действий |
| `aggregate_fn_name` | `weighted_average` | Функция агрегации перекрывающихся chunk'ов |

### Масштабирование на рой

- SmolVLA занимает ~2 ГБ GPU-памяти при inference — на одном A100 (80 ГБ) можно параллельно обслуживать множество PolicyServer-инстансов
- RobotClient может подключаться к удалённому PolicyServer по сети — сервер в облаке, клиенты на роботах
- Для мониторинга доступна визуализация размера очереди действий в реальном времени

## 4. Интеграция камер

### Поддерживаемые камеры LeRobot

| Тип | Применение в AgentsSwarm |
|-----|--------------------------|
| **OpenCVCamera** | USB-камеры на роботах, веб-камеры для мониторинга |
| **ZMQCamera** | Сетевые IP-камеры в зоне работы роботов |
| **RealSenseCamera** | Камеры глубины Intel RealSense на манипуляторах |

### Режимы захвата кадров

- **`read()`** — блокирующий вызов, используется в простых сценариях последовательного захвата
- **`async_read(timeout_ms)`** — возвращает последний не потреблённый кадр, блокирует только при пустом буфере. Оптимален для **control loop** робота, синхронизированного с FPS камеры
- **`read_latest(max_age_ms)`** — мгновенно возвращает последний кадр (может быть устаревшим). Подходит для **мониторинга и UI** на Dashboard AgentsSwarm

### Связь с ROS2 Bridge

Камеры LeRobot подключаются к роботам напрямую через USB или сеть. Для интеграции с ROS2 на Edge-ноде AgentsSwarm:

- Кадры с камер LeRobot преобразуются в ROS2 Image-топики через `cv_bridge`
- SmolVLA/X-VLA на Edge подписываются напрямую на камеры LeRobot (без ROS2), сокращая латентность
- ROS2 Bridge обеспечивает доступ к тем же кадрам для других ROS2-нод (навигация, SLAM)

## 5. Симуляция с IsaacLab Arena

### Роль в AgentsSwarm

NVIDIA IsaacLab Arena интегрируется с LeRobot для **обучения и оценки политик в GPU-ускоренной симуляции**. Это критично для AgentsSwarm, так как позволяет:

- Обучать SmolVLA/X-VLA на тысячах эпизодов без физических роботов
- Оценивать политики перед деплоем на реальный рой
- Тестировать поведение роя в контролируемых условиях

### Доступные среды и роботы

- **Гуманоидные роботы**: GR1, G1, Galileo с различными конфигурациями
- **Задачи манипуляции**: открывание дверей, pick-and-place, нажатие кнопок
- **Локомоция + манипуляция**: одновременное перемещение и работа руками
- **RTX-рендеринг**: фотореалистичные изображения с отражениями и преломлениями — визуально близки к реальным камерам

### Предобученные политики SmolVLA для IsaacLab

| Политика | Задача | Результат |
|---------|--------|----------|
| `nvidia/smolvla-arena-gr1-microwave` | Манипуляция с микроволновкой (GR1) | Оценена в IsaacLab Arena |
| `LightwheelAI/smolvla-double-piper-pnp` | Pick-and-place (Double Piper, бимануальный) | 100 эпизодов оценки |

### Процесс для AgentsSwarm

1. Создать или выбрать среду IsaacLab Arena, соответствующую задачам роя
2. Собрать датасет через телеоперацию в симуляторе
3. Обучить SmolVLA/X-VLA на этом датасете через `lerobot-train`
4. Оценить в симуляции через `lerobot-eval`
5. При удовлетворительных результатах — перенести на реальных роботов (sim-to-real)

## 6. EnvHub — хаб окружений

### Применение в AgentsSwarm

EnvHub позволяет загружать симуляционные окружения с HuggingFace Hub одной строкой. Для AgentsSwarm это означает:

- **Создание кастомных окружений**: моделирование конкретных сценариев работы роя (склад, производственная линия, открытая территория) и публикация на Hub
- **Версионирование**: окружения версионируются через Git, привязка к конкретному коммиту для воспроизводимости экспериментов
- **Мультизадачность**: одно окружение может содержать несколько задач (pick-place, patrol, inspect), возвращаемых как вложенный словарь сред
- **Стандартный интерфейс**: все окружения реализуют `gym.vector.VectorEnv`, что обеспечивает совместимость с LeRobot и стандартными RL-фреймворками

### Безопасность

EnvHub требует явного `trust_remote_code=True` для выполнения кода. В production AgentsSwarm рекомендуется:

- Использовать только окружения из доверенных источников (NVIDIA, HuggingFace, внутренние репозитории)
- Привязывать к конкретным commit hash
- Запускать в изолированных контейнерах

## 7. Environment Processors

### Роль в AgentsSwarm

Environment Processors — слой, разделяющий трансформации данных среды (формат наблюдений, системы координат) от трансформаций политики (нормализация, токенизация). Это критично для AgentsSwarm, где:

- Разные типы роботов в рое имеют разные форматы сенсорных данных
- Разные камеры имеют разные ориентации и разрешения
- Одна политика (SmolVLA/X-VLA) должна работать с разными роботами

### Пайплайн обработки данных

```
Среда (робот) → предобработка → Environment Preprocessor → Policy Preprocessor → Inference → Policy Postprocessor → Environment Postprocessor → Действие (робот)
```

### Кастомные процессоры для AgentsSwarm

Для каждого типа робота в рое создаётся свой Environment Processor:

- **Преобразование состояния**: вложенные словари ROS2 (`joint_states`, `end_effector_pose`) → плоский тензор для модели
- **Обработка камер**: коррекция ориентации, ресайз, нормализация для конкретной конфигурации камер робота
- **Преобразование действий**: выход модели (нормализованный вектор) → команды для конкретных контроллеров робота (joint trajectory, velocity, gripper)
- **Фильтрация координат**: преобразование между системами координат (world frame ↔ base frame ↔ end-effector frame)

Процессоры регистрируются через `ProcessorStepRegistry` и подключаются автоматически по типу окружения.

## 8. Сбор данных и обучение

### Рекомендации по датасетам из опыта LeRobot

| Параметр | Рекомендация | Источник |
|----------|-------------|----------|
| Число эпизодов | ≥50 на задачу | SmolVLA paper |
| Вариативность | ≥10 эпизодов на каждую вариацию (позиция объекта, условия) | Эксперименты SmolVLA (5 позиций × 10 эпизодов) |
| Минимум для работоспособности | ~50 эпизодов (25 было недостаточно) | SmolVLA paper |
| Формат | LeRobot Dataset (HuggingFace) | Стандарт LeRobot |

### Пайплайн обучения для AgentsSwarm

1. **Телеоперация**: оператор управляет роботом через ROS2 телеоп-интерфейс, данные записываются в формате LeRobot
2. **Загрузка на Hub**: датасет публикуется на HuggingFace Hub (приватный репозиторий для внутренних данных)
3. **Обучение SmolVLA**: `lerobot-train --policy.path=lerobot/smolvla_base --dataset.repo_id=<repo> --steps=20000 --batch_size=64` — ~4 часа на одном A100
4. **Обучение X-VLA** (для кросс-платформенных сценариев): `lerobot-train --policy.path=lerobot/xvla-base --policy.action_mode=auto --policy.dtype=bfloat16 --steps=20000`
5. **Оценка в симуляции**: `lerobot-eval` с IsaacLab Arena
6. **Оценка на реальном роботе**: `lerobot-record` с записью результатов
7. **Деплой на рой**: OTA-обновление через MinIO + MQTT

### X-VLA: адаптация нового типа робота

Когда в рой AgentsSwarm добавляется новый тип робота:

1. Выбрать ближайший Domain ID из таблицы предобученных (Bridge=0, RT1=1, ... AGIBOT=9)
2. Собрать ~50 демонстраций нового робота
3. Обучить Soft Prompts + policy transformer: ~3000 шагов с `policy.train_soft_prompts=true`
4. При необходимости создать Custom Action Mode для нестандартного пространства действий
5. Оценить в симуляции и на реальном роботе
6. Развернуть на рой

## 10. Сводная таблица компонентов LeRobot

| Компонент LeRobot | Модуль AgentsSwarm | Назначение |
|-------------------|-------------------|------------|
| SmolVLA (`smolvla_base`) | SmolVLA Service (Cloud + Edge) | Генерация действий манипуляции |
| X-VLA (`xvla-base`) | SmolVLA Service (Cloud) | Кросс-платформенное управление гетерогенным роем |
| Async Inference (PolicyServer/RobotClient) | SmolVLA Service + RobotEdge | Безлаговое управление через client-server |

| IsaacLab Arena | Training Pipeline | GPU-ускоренная симуляция для обучения и оценки |
| `lerobot-train` | Training Pipeline | Дообучение SmolVLA/X-VLA на данных AgentsSwarm |
| `lerobot-record` | Evaluation Pipeline | Оценка на реальных роботах |
| LeRobot Dataset | Data Pipeline | Стандартный формат данных телеоперации |
