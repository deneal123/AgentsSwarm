# Интеграция ROS 2 Jazzy Desktop в проект AgentsSwarm

## Введение

Данный документ описывает, как Docker-образ ROS 2 Jazzy Desktop (Dockerfile.vnc) и связанные с ним материалы могут быть использованы в контексте платформы **AgentsSwarm** — системы управления роем роботов с AI-оркестрацией. Рассматриваются конкретные сценарии, точки интеграции с микросервисной архитектурой платформы и рекомендации по адаптации образа для production-развёртывания.

---

## 1. Роль образа в архитектуре AgentsSwarm

### 1.1 Где располагается в архитектуре

В шестислойной архитектуре AgentsSwarm данный образ относится к слою **RobotEdge** — программному стеку, работающему непосредственно на роботе (или эмулирующему робота для разработки). Он закрывает сразу несколько компонентов Edge-слоя:

- **ROS2 Bridge** — трансляция ROS 2 топиков в форматы, доступные облачной платформе (через Foxglove Bridge / WebSocket или MQTT)
- **Edge Agent Runtime** — среда выполнения ROS 2 узлов, управляющих сенсорами и актуаторами
- **Инструменты отладки** — RViz2, rqt, Foxglove Studio для визуализации и диагностики

### 1.2 Два режима использования

| Режим | Назначение | Целевая аудитория |
|-------|-----------|-------------------|
| **Development / Simulation** | Разработка и тестирование ROS 2 узлов без физического робота | Разработчики, QA |
| **Edge Runtime (адаптированный)** | Базовый образ для контейнеризации ROS 2 стека на реальном роботе | DevOps, Edge-инженеры |

## 2. Сценарий 1: Среда разработки ROS 2 Bridge

### Что это даёт

Образ предоставляет полностью сконфигурированную среду ROS 2 Jazzy с GUI, в которой разработчик может создавать и тестировать ROS 2 узлы, реализующие ROS2 Bridge для AgentsSwarm, без необходимости иметь физического робота.

### Какие компоненты AgentsSwarm можно разрабатывать

**a) Узлы трансляции топиков (Topic Translator Nodes)**

Основная задача ROS2 Bridge в AgentsSwarm — преобразование стандартных ROS 2 сообщений (sensor_msgs, nav_msgs, geometry_msgs) в Protobuf/JSON для передачи по MQTT в облако. В данном образе можно:

- Создать ament_python пакет (по аналогии с my_robot_controller из README_2) для Bridge-узлов
- Подписаться на стандартные ROS 2 топики (/camera/image_raw, /scan, /odom, /cmd_vel)
- Реализовать сериализацию в Protobuf и публикацию в MQTT (через paho-mqtt или аналогичную библиотеку)
- Тестировать с помощью turtlesim или симулированных данных (ros2 topic pub)

**b) Узлы агрегации и фильтрации данных**

Перед отправкой в облако Edge должен фильтровать и агрегировать данные (не отправлять каждый кадр камеры). В образе можно разрабатывать узлы, которые:

- Сэмплируют данные телеметрии (каждый N-й кадр, усреднение за окно)
- Детектируют «интересные» события для приоритетной отправки
- Сжимают изображения перед передачей (или формируют ссылки на MinIO)

**c) Узлы приёма облачных команд**

Обратный поток: облако (Orchestrator) отправляет команды роботу через MQTT. Bridge должен преобразовать их в ROS 2 сообщения (например, geometry_msgs/Twist для /cmd_vel). Эту логику удобно разрабатывать и тестировать в данном образе.

### Рабочий процесс разработчика

1. Собрать и запустить контейнер с монтированием workspace
2. Подключиться через VS Code Remote Containers или VNC в браузере (http://localhost:6080/vnc.html)
3. Создать ROS 2 пакет в ~/ros2_ws/src/
4. Разработать Bridge-узлы
5. Тестировать с помощью ros2 topic pub / ros2 topic echo / rqt_graph
6. Собрать через colcon build --symlink-install
7. Запушить в Git (общий репозиторий AgentsSwarm)

## 3. Сценарий 2: Foxglove Bridge → Frontend интеграция

### Что это даёт

В образе предустановлен **ros-jazzy-foxglove-bridge** — WebSocket-мост (порт 8765), через который внешние клиенты (в том числе веб-интерфейсы) могут подписываться на ROS 2 топики в реальном времени.

### Как это связано с Frontend AgentsSwarm

Frontend AgentsSwarm включает компонент **3D-визуализация** (Three.js / react-three-fiber). Foxglove Bridge предоставляет стандартизированный WebSocket-протокол, через который Frontend может получать:

- Позиции робота (/odom, /tf)
- Данные LiDAR (/scan)
- Изображения с камеры (/camera/image_compressed)
- Карту (/map)
- Пользовательские маркеры (/visualization_markers)

### Варианты архитектуры

**Вариант A: Прямое подключение Frontend → Foxglove Bridge**

Подходит для разработки и небольших инсталляций (1–3 робота). Frontend подключается напрямую к Foxglove Bridge каждого робота. Протокол: WebSocket на порту 8765.

Преимущества: простота, минимальная задержка.
Ограничения: не масштабируется, нет единой точки доступа.

**Вариант B: Foxglove Bridge → Gateway → Frontend**

Для production: данные с Foxglove Bridge агрегируются через Gateway Service, который мультиплексирует потоки от всех роботов и предоставляет единый WebSocket-канал для Frontend.

Преимущества: масштабируемость, единая точка авторизации.
Ограничения: дополнительная задержка, сложность маршрутизации.

**Вариант C: Foxglove Bridge → MQTT → Gateway → Frontend**

Гибридный вариант: Foxglove Bridge на Edge конвертирует ROS 2 данные в WebSocket, но вместо прямого подключения клиента данные перенаправляются в MQTT (через дополнительный Bridge-узел), а далее через стандартный MQTT → Gateway → WebSocket путь AgentsSwarm.

Рекомендация: использовать вариант C для production, вариант A для локальной разработки и отладки.

## 4. Сценарий 3: Удалённая отладка роботов

### Проблема

При развёртывании роботов в полевых условиях необходимо иметь возможность подключаться к ROS 2 стеку робота, визуализировать данные сенсоров и диагностировать проблемы.

### Решение через noVNC

Образ предоставляет доступ к полному графическому рабочему столу через браузер (noVNC, порт 6080). Это означает:

- Оператор может открыть RViz2 удалённо и видеть модель робота, облако точек, карту
- Оператор может запустить rqt для мониторинга топиков, параметров, логов
- Оператор может использовать teleop_twist_keyboard для ручного управления роботом
- Для доступа нужен только браузер — никакого специального ПО

### Интеграция с AgentsSwarm

В Dashboard UI платформы можно добавить кнопку «Remote Debug», которая:

1. Через Gateway API запрашивает открытие VNC-порта для указанного робота
2. Открывает iframe или новую вкладку с noVNC (http://robot_ip:6080/vnc.html)
3. Оператор получает полный GUI-доступ к ROS 2 стеку конкретного робота

Для безопасности: туннелирование через SSH или VPN, замена стандартного пароля «student» на динамически генерируемый токен, ограничение времени сессии.

## 5. Сценарий 4: Базовый образ для Edge Runtime

### Адаптация Dockerfile.vnc для production

Текущий образ ориентирован на разработку и обучение (тяжёлый Desktop Full, VNC, шрифты, IDE-инструменты). Для production Edge Runtime на реальном роботе его необходимо адаптировать.

### Что оставить

- Базовый образ: `osrf/ros:jazzy-desktop-full` заменить на `osrf/ros:jazzy-ros-base` (значительно легче)
- Python-библиотеки: rclpy, numpy, opencv (необходимы для Edge AI Proxy)
- colcon, rosdep (для сборки workspace)
- foxglove-bridge (для отладки, можно включать по флагу)

### Что убрать

- XFCE4, VNC, noVNC (не нужны на headless-роботе, либо включаются опционально)
- Шрифты, vim, nano (экономия места)
- turtlesim (учебный инструмент)
- Foxglove Studio desktop (тяжёлый, используем веб-версию)

### Что добавить

- **MQTT-клиент**: paho-mqtt или mosquitto-clients для связи с EMQX
- **gRPC**: grpcio + protobuf для связи с облачными сервисами
- **Edge AI Proxy зависимости**: onnxruntime (или tensorrt для Jetson)
- **SmolVLA Edge runtime**: оптимизированная модель и inference engine
- **Connectivity Manager**: скрипты мониторинга сети и переключения online/offline
- **Watchdog**: процесс мониторинга здоровья основных узлов

### Результат: два производных образа

| Образ | Базируется на | Назначение |
|-------|--------------|-----------|
| `agentswarm/edge-dev:latest` | Dockerfile.vnc (текущий) + MQTT + gRPC | Разработка и тестирование Edge-стека |
| `agentswarm/edge-runtime:latest` | ros:jazzy-ros-base + минимальный набор | Production-образ для реального робота |

## 6. Сценарий 5: CI/CD и автоматическое тестирование

### Непрерывная интеграция ROS 2 пакетов

Образ (или его облегчённый вариант) может использоваться в CI/CD пайплайне AgentsSwarm для:

- **Сборки ROS 2 пакетов**: colcon build в Docker-контейнере на CI-раннере
- **Запуска тестов**: colcon test (unit-тесты узлов, lint, copyright checks)
- **Интеграционного тестирования**: запуск нескольких узлов, проверка трансляции топиков, проверка MQTT-интеграции

### Пример CI-шага

Сборка и тест Bridge-пакетов:
1. CI-раннер поднимает контейнер из agentswarm/edge-dev
2. Монтирует src/ из репозитория
3. Выполняет colcon build
4. Выполняет colcon test
5. При успехе — собирает agentswarm/edge-runtime и пушит в Container Registry
6. edge-runtime доставляется на роботов через OTA-обновление

### Тестирование без физических роботов

С помощью `ros2 topic pub` и `ros2 bag play` можно эмулировать данные сенсоров, проверяя корректность работы Bridge-узлов. Для более полной симуляции — интеграция с Gazebo (поддерживается в ros:jazzy-desktop-full).

## 9. Сетевая интеграция

### Порты и протоколы

| Порт | Протокол | Назначение | Связь с AgentsSwarm |
|------|----------|-----------|---------------------|
| 5901 | VNC (TCP) | Прямое VNC-подключение | Отладка, туннелируется через VPN |
| 6080 | HTTP/WebSocket | noVNC веб-доступ | Интеграция с Dashboard UI |
| 8765 | WebSocket | Foxglove Bridge | Данные для Frontend / Gateway |
| 1883/8883 | MQTT (добавить) | Связь с EMQX-брокером | Основной канал Edge ↔ Cloud |
| 50051 (добавить) | gRPC | Связь с Orchestrator/Triton | Запросы inference, команды |

### Сетевая топология в Docker Compose

Для локальной разработки рекомендуется Docker Compose, объединяющий:

- Контейнер ROS 2 (данный образ) — эмуляция робота
- Контейнер EMQX — MQTT-брокер
- Контейнер Gateway (FastAPI) — API-шлюз
- Контейнер Redis — кэш и Feature Store

Все контейнеры в одной Docker-сети, что позволяет тестировать полный поток данных: ROS 2 → Bridge → MQTT → Gateway → Redis.

## Заключение

Docker-образ ROS 2 Jazzy Desktop из ros_edge_bridge является ценным фундаментом для Edge-слоя AgentsSwarm. Он предоставляет: готовую среду разработки и тестирования ROS 2 узлов, WebSocket-мост (Foxglove Bridge) для интеграции с Frontend, инструменты удалённой отладки (noVNC, RViz2, rqt), и базу для создания production Edge Runtime. Адаптация этого образа под специфику AgentsSwarm позволит значительно ускорить разработку ROS2 Bridge, Edge AI Proxy и системы автономной работы роботов.
