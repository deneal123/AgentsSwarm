# План разработки первоначального SimulationApp

Этот документ описывает шаги по созданию базового приложения симуляции (SimulationApp) в NVIDIA Isaac Sim с использованием Python скриптинга. В симуляции будет создана стартовая сцена и добавлен первый мобильный робот, заложив основу для масштабирования в мультиагентную систему.

## Цель

Создать управляемую скриптами сцену в Isaac Sim (ИСКЛЮЧИТЕЛЬНО в headless режиме, так как сервер работает на базе GPU без дисплея; визуализация будет производиться через WebRTC стриминг), добавить туда наземную плоскость и одного мобильного робота (например, LIMO или Nova Carter, без манипуляторов), оснащенного камерой. 
В долгосрочной перспективе это часть магистерской диссертации **"Организация кооперативного восприятия сцены в группе автономных агентов на основе обмена визуальной информации"**. Разрабатываемая среда станет основой для симуляции роя роботов, управляемых оркестратором агентов через ROS 2 и ROS-MCP-Server.

## Предварительные условия

- Окружение `uv` настроено, зависимости `nvidia_isaac_simulation` установлены (`isaacsim` включен).
- Пройдена активация лицензии (EULA), пакеты Isaac Sim могут быть запущены через Python.

## Шаги реализации

### 1. Подготовка конфигурации (Настройки проекта)
- Обновить/дополнить файлы в директории `src/nvidia_isaac_simulation/config/`:
  - Определить жесткую конфигурацию симуляции: всегда `headless=True`, включение расширения WebRTC для стриминга (порты, битрейт, fps, разрешение, опционально STUN/TURN), устройство, настройки физики.
  - Задать параметры робота (тип - LIMO/Carter, начальная позиция, путь к USD ассету, наличие сенсоров/камер).
  - Зарезервировать параметры под мультиагентность (конфигурация количества роботов, смещения генерации позиций).
  - Учесть переменные окружения (например, `ACCEPT_EULA=Y`, CUDA/RTX флаги, пути к ассетам); задокументировать обязательные env для headless/WebRTC.
  - Для WebRTC задать: `WEBRTC_PORT` (например 8211), `WEBRTC_BITRATE`, `WEBRTC_FPS`, `WEBRTC_RESOLUTION`, `WEBRTC_STUN`/`TURN` (при необходимости NAT), `WEBRTC_LOG_LEVEL`; предусмотреть place-holder в config TOML.

### 2. Создание ядра симуляции (Core App)
- Создать в модуле `src/nvidia_isaac_simulation` основной класс (например, `AppCore` в новом файле `app.py`).
- Логика этого класса:
  - Инициализация контекста `SimulationApp` перед любыми другими импортами пакетов Isaac Sim/Omniverse (как требует документация: `from isaacsim.simulation_app import SimulationApp; simulation_app = SimulationApp({"headless": True})`).
  - Убедиться, что загружается и активируется расширение для WebRTC (например, `omni.services.streaming.webrtc` / `omni.kit.webrtc.*`), включить через `simulation_app.ext_manager` или конфиг. Проверить, что сервис слушает нужный порт и поднимает default route `/streaming/webrtc`.
  - Метод для запуска и управления жизненным циклом (запуск главного цикла, корректное завершение через `.close()`).

### 2.1 Настройка WebRTC стриминга (детализация)
- Включить extension: `omni.services.streaming.webrtc` (или соответствующий бандл Isaac Sim 6.0), проверить зависимости `omni.services.core`.
- В конфиге: указать `rtc_signaling_host`/`rtc_signaling_port` (по умолчанию 8211), `rtc_ice_servers` (STUN/TURN), `max_framerate`, `max_bitrate`, `stream_resolution`.
- Прописать SDP offer/answer флоу: сервер поднимает signaling endpoint; клиент (WebRTC viewer) шлет offer, получает answer, ICE candidates обмениваются автоматически.
- Опционально: включить `webrtc.auth.enabled=false` на тестовом стенде либо задать токен/Basic Auth для продакшена.
- Логи и метрики: включить логгирование стриминга (битрейт, fps, packet loss) для диагностики headless качества.

### 3. Настройка сцены (Scene Setup)
- Добавить метод или отдельный класс для инициализации `World` (используя `isaacsim.core.api.world.World` или аналогичный Experimental API).
- Загрузить базовое окружение:
  - Использовать `isaacsim.storage.native.get_assets_root_path()` для нахождения базовых ассетов.
  - Добавить поверхность (Ground Plane) либо загрузить дефолтное USD-окружение (например, `assets_root_path + "/Isaac/Environments/Grid/default_environment.usd"`).
  - Задать параметры симуляции: фиксированный `dt`, `physics_dt`, число подшагов, включение GPU PhysX при наличии.

### 4. Интеграция робота (без манипуляторов)
- Использовать Python API и расширение Isaac Sim для спавна мобильных роботов (LIMO, Carter) на сцене. Разместить хотя бы одного мобильного робота.
- Оснащение сенсорами: Добавить виртуальную камеру (RGB, Depth) к роботу, подготовить пайплайн для считывания/обмена визуальной информацией.
- Настроить контроллер базы (Wheeled Robot Controller / Differential Drive) для отправки навигационных команд агентами. 
- Написать масштабируемую функцию спавна `spawn_robots(count: int)`, которая в будущем позволит инициализировать рой из нескольких роверов на заданных координатах.

### 5. Обновление CLI 
- Отредактировать файл `src/nvidia_isaac_simulation/cli.py` и `__main__.py`, чтобы добавить команду запуска симуляции.
- Реализовать команду (например, `start-sim`), которая инициализирует конфигурацию, запускает `AppCore`, строит сцену и держит симуляцию запущенной в цикле `while simulation_app.is_running(): world.step(...)`.

### 6. Документация и запуск (Testing)
- Написать инструкцию в `README.md` (или обновить `docs`) о том, как запустить скрипт в headless/WebRTC режиме (например: `uv run python -m nvidia_isaac_simulation --headless --webrtc` или отдельная команда `start-sim`).
- Описать, как подключаться WebRTC-клиентом (порт, протокол, авторизация, sample SDP), и какие метрики/логи смотреть при headless запуске.
  - Пример подключения: открыть WebRTC viewer (или свой клиент) и отправить SDP offer на `http://<host>:<port>/streaming/webrtc` (или ws://, если использует вебсокет-сигналинг), получить SDP answer, затем ICE-кандидаты; указать порт 8211 по умолчанию.
  - Документировать минимальный набор curl-команд или утилиту для теста сигналинга, чтобы убедиться, что сервис поднят.

## Дальнейшие шаги (после реализации базовой сцены)

- Добавление Omnigraph-узлов для интеграции ROS 2 (`isaacsim-ros2`), в частности - публикаторов из камер в топики `sensor_msgs/Image`.
- Настройка `rosbridge` внутри/поверх симуляции для взаимодействия с `ros-msp-server`. Это свяжет агентов (LLM-оркестратор) с симуляцией.
- Построение системы **кооперативного восприятия**:
  - Агенты должны будут "видеть" каждый свою камеру и обмениваться визуальной информацией (управление топиками и совместной картой).
  - Сплочение роя роботов (LIMO/Carter) под единым агентом-оркестратором для распределенного выполнения общих задач.
 - Синхронизация времени и QoS в ROS 2 (clock, tf, sensordata) для корректной работы в рое; продумать компрессию/частоту кадров для WebRTC/ROS топиков.
