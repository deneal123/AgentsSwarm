# Neo4j — Графовая база данных

## Роль

Neo4j хранит топологию среды, связи между объектами, историю взаимодействий агентов и семантические связи (например, зона A смежна зоне B). Графовая модель данных идеально подходит для задач навигации, поиска путей и анализа связей. Взаимодействие осуществляется через **Neo4j Python Driver** с поддержкой языка запросов Cypher.

---

## Python Driver

### Установка и требования

- Пакет: `neo4j` (pip install neo4j)
- Python >= 3.10
- Драйвер последней версии (6.x) поддерживает Neo4j 4.4, 5.x и 2025.x
- Опциональный Rust-расширение `neo4j-rust-ext` — ускорение в 3–10 раз по сравнению с чистым Python-драйвером. Устанавливается рядом или вместо основного пакета, API полностью идентичен

### Подключение

Основной класс — `GraphDatabase.driver(URI, auth=AUTH)`. URI определяет протокол и адрес:

| Схема URI | Описание | Порт |
|-----------|----------|------|
| `neo4j://` | Маршрутизирующее подключение (routing). Драйвер получает таблицу маршрутизации кластера и направляет запросы на primaries (запись) или secondaries (чтение) | 7687 |
| `neo4j+s://` | То же, но с TLS-шифрованием | 7687 |
| `bolt://` | Прямое подключение к конкретной ноде (без routing) | 7687 |
| `bolt+s://` | Прямое подключение с TLS | 7687 |

Аутентификация: кортеж (username, password). Также поддерживаются Kerberos, Bearer и пользовательские auth-методы.

Метод `verify_connectivity()` позволяет проверить подключение сразу после создания драйвера (валидность credentials, совместимость версий).

### Свойства Driver объекта

- **Immutable** — настройки не изменяются после создания
- **Thread-safe** — безопасен для использования из нескольких потоков
- **Дорогой в создании** — приложение должно создавать только один экземпляр и переиспользовать его
- Для работы под разными пользователями — использовать impersonation (параметр `auth_` или `impersonated_user_` в запросе), а не создание нового Driver

### Подключение к кластеру

При подключении к кластеру Neo4j драйвер получает **таблицу маршрутизации** (routing table), содержащую информацию о всех машинах кластера и их ролях. Таблица периодически обновляется. Варианты подключения:

- Через hostname с несколькими DNS A/AAAA записями (рекомендуется)
- Через custom address resolver — для случаев, когда адреса нод известны, но не публикуются через DNS
- Через адрес любой ноды кластера — драйвер обнаружит остальные (наименее отказоустойчивый вариант)

## Модель данных (Cypher)

### Узлы (Nodes)

| Label | Свойства | Описание |
|-------|----------|----------|
| `:Robot` | name, model, status, battery_level, firmware_version | Физический робот |
| `:Zone` | zone_id, name, type (work/charge/storage), coordinates | Зона на карте |
| `:Object` | object_id, class_name, confidence, position | Детектированный объект |
| `:Task` | task_id, type, status, priority, created_at | Задача из Orchestrator |
| `:ChargingStation` | station_id, location, capacity, available_slots | Зарядная станция |
| `:Person` | person_id, name, role | Оператор / пользователь |
| `:Model` | model_name, version, framework | ML-модель (Triton/vLLM) |

### Связи (Relationships)

| Связь | Описание | Свойства |
|-------|----------|----------|
| `(Robot)-[:IN_ZONE]->(Zone)` | Робот находится в зоне | since (timestamp) |
| `(Robot)-[:EXECUTED]->(Task)` | Робот выполнил задачу | started_at, finished_at, result |
| `(Object)-[:LOCATED_IN]->(Zone)` | Объект находится в зоне | detected_at, confidence |
| `(Zone)-[:ADJACENT_TO]->(Zone)` | Зоны смежные | distance, traversal_time |
| `(Robot)-[:DETECTED]->(Object)` | Робот обнаружил объект | detected_at, camera_id |
| `(Task)-[:ASSIGNED_TO]->(Robot)` | Задача назначена роботу | assigned_at |
| `(Robot)-[:USES_MODEL]->(Model)` | Робот использует модель | deployed_at |
| `(Person)-[:MANAGES]->(Robot)` | Оператор управляет роботом | — |
| `(ChargingStation)-[:LOCATED_IN]->(Zone)` | Станция в зоне | — |

## Запросы (execute_query)

### Основной метод

Метод `driver.execute_query()` — рекомендуемый способ выполнения запросов. Возвращает кортеж из трёх элементов:

- **records** — список объектов Record с результатами
- **summary** — метаданные выполнения (время, counters — nodes_created, relationships_created и т.д.)
- **keys** — список доступных ключей (имён столбцов) в результате

Драйвер автоматически повторяет запрос при transient-ошибках (временная недоступность сервера).

### Параметры запросов

Параметры запроса передаются как keyword arguments и используются через плейсхолдеры `$param` в Cypher. **Никогда** не конкатенировать значения напрямую в строку запроса — это необходимо для:

- **Производительности**: Neo4j кэширует скомпилированные запросы, но только если структура запроса неизменна
- **Безопасности**: защита от Cypher injection

Альтернативно параметры можно передать словарём через `parameters_=dict`.

### Конфигурация запросов

| Параметр | Описание |
|----------|----------|
| `database_` | Имя базы данных (рекомендуется всегда указывать — экономит round-trip) |
| `routing_="r"` | Маршрутизация на read-реплики в кластере (для READ-запросов) |
| `auth_` | Выполнение запроса под другим пользователем (без создания нового Driver) |
| `impersonated_user_` | Impersonation — выполнение от имени пользователя без знания пароля (требует соответствующих прав) |
| `timeout` | Timeout для запроса в Query объекте |
| `metadata` | Метаданные транзакции (видны в логах сервера) |

## Примеры запросов AgentsSwarm

### Навигация

- **Ближайшая зарядная станция к роботу**: MATCH path через ADJACENT_TO связи с алгоритмом кратчайшего пути
- **Оптимальный маршрут между зонами**: MATCH shortest path (Zone)-[:ADJACENT_TO*]-(Zone) с учётом traversal_time
- **Все роботы в заданной зоне**: MATCH (r:Robot)-[:IN_ZONE]->(z:Zone {zone_id: $zone_id}) RETURN r

### Аналитика

- **Поиск объектов заданного класса**: MATCH (o:Object {class_name: $class})-[:LOCATED_IN]->(z:Zone) WHERE o.confidence > $threshold RETURN o, z
- **История выполнения задач роботом**: MATCH (r:Robot {name: $name})-[:EXECUTED]->(t:Task) RETURN t ORDER BY t.created_at DESC
- **Root-cause анализ**: обход графа связей от инцидента через задачи, роботов, модели для нахождения первопричины
- **Загруженность зон**: MATCH (r:Robot)-[:IN_ZONE]->(z:Zone) RETURN z.name, count(r) AS robot_count

## Трансформация результатов

### Pandas DataFrame

Драйвер может преобразовать результат в pandas DataFrame через `result_transformer_=neo4j.Result.to_df`. Опции:

- **expand** — рекурсивное развёртывание вложенных структур
- **parse_dates** — конвертация DateTime объектов в pandas.Timestamp

### Граф (Graph)

Трансформер `result_transformer_=neo4j.Result.graph` возвращает объект Graph с коллекциями `nodes` и `relationships` — для визуализации (pyvis) или дальнейшей обработки графовых данных.

### Пользовательские трансформеры

Параметр `result_transformer_` принимает произвольную функцию, которая обрабатывает объект Result и возвращает любую структуру данных. Доступные методы Result: single(), fetch(), peek(), consume(), values().

## Транзакции и сессии

### Managed Transactions (рекомендуемый)

Через `session.execute_read()` и `session.execute_write()` — драйвер автоматически повторяет при transient-ошибках. Функция-обработчик получает объект transaction (tx) и вызывает `tx.run()` для выполнения Cypher-запросов.

### Implicit Transactions

Через `session.run()` — базовый способ без автоматических повторов. Необходимо потреблять все записи (consume()) для гарантированного коммита. Единственный способ для запросов `CALL { ... } IN TRANSACTIONS` (batch-импорт CSV).

### Bookmarks — Каузальная консистентность

По умолчанию `execute_query()` автоматически управляет bookmarks — последующие запросы видят изменения предыдущих. Для нескольких сессий bookmarks нужно передавать явно:

- Собрать bookmarks из сессий через `session.last_bookmarks()`
- Передать их в новую сессию через параметр `bookmarks`

Bookmarks обеспечивают каузальную консистентность в кластере, но могут негативно влиять на производительность (ожидание репликации). Использовать только при необходимости.

## Asyncio

Neo4j Python Driver поддерживает асинхронную работу через `AsyncGraphDatabase.driver()`:

- `AsyncDriver` создаётся аналогично синхронному
- Все методы (execute_query, session, tx.run) являются корутинами и требуют `await`
- Совместим с asyncio event loop (подходит для интеграции в FastAPI)
- Рекомендуется Python 3.10+ для стабильной работы async driver

## Обработка ошибок

Все серверные исключения — подклассы `Neo4jError`. Свойства:

- **code** — стабильный код ошибки Neo4j (Neo.ClientError.Statement.SyntaxError и т.д.)
- **message** — текстовое описание (нестабильно, не полагаться)
- **gql_status** — GQL-статус код (более гранулярный, чем Neo4j error code)
- **is_retryable()** — определяет, является ли ошибка transient (стоит ли повторять)

GQL-статус коды позволяют точно различать типы ошибок для дифференцированной обработки (42001 — синтаксическая ошибка, 42NFF — forbidden).

## Репликация и бэкап

- **Кластер Neo4j**: primaries для записи, secondaries (read replicas) для чтения
- Routing через `neo4j://` URI — автоматическое распределение read/write нагрузки
- Регулярный экспорт графов и snapshot-резервные копии
- Causal cluster с автоматическим failover
- Мониторинг: query log analysis, transaction counters

---

## Best Practices

- Всегда указывать `database_` в запросах — экономит network round-trip
- Использовать `routing_="r"` для READ-запросов в кластере — распределение на read-реплики
- Один Driver на приложение, переиспользовать через DI
- Параметризованные запросы через `$param` — никогда не конкатенировать значения
- execute_query() вместо session.run() для автоматических retry
- Bookmarks только при необходимости каузальной консистентности между сессиями
- neo4j-rust-ext для критичных по производительности сценариев (3–10x ускорение)
- Индексы на часто запрашиваемых свойствах (robot_id, zone_id, class_name)
- DETACH DELETE для удаления узлов со всеми связями
