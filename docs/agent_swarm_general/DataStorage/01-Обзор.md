# Data Storage — Обзор

## Назначение

Подсистема хранения отвечает за долговременное хранение телеметрии, изображений, моделей, графовой информации и временных рядов, а также за быстрый доступ к оперативным данным. Архитектура построена на принципе **polyglot persistence** — каждая база данных выбрана для оптимального решения конкретного класса задач.

---

## Компоненты

| Хранилище | Тип | Назначение в AgentsSwarm | Python-клиент | Протокол |
|-----------|-----|--------------------------|---------------|----------|
| **InfluxDB 3.0** | Time Series DB | Телеметрия роботов, системные метрики, события | influxdb3-python (influxdb_client_3) | HTTP + Arrow Flight (gRPC) |
| **Neo4j** | Graph DB | Топология среды, связи объектов, история взаимодействий агентов | neo4j (Python Driver) | Bolt (7687) / neo4j:// (routing) |
| **Redis** | In-Memory KV + модули | Кэш, Feature Store, Pub/Sub, Streams, TimeSeries, поиск | redis-py (redis) | RESP v2/v3 (6379) |
| **MinIO** | Object Storage (S3-совместимый) | Изображения, логи, веса моделей, артефакты обучения | minio (Python SDK) | S3 API (HTTP/HTTPS, 9000) |
| **PostgreSQL** | Relational DB | Пользователи, задачи, роботы, инциденты, аудит | SQLAlchemy ORM (sqlalchemy) | PostgreSQL (5432) |

## Принцип Polyglot Persistence

Каждый тип данных направляется в оптимальное хранилище:

- **Временные ряды** (телеметрия 10–50 Гц, метрики GPU) → **InfluxDB** — оптимизирована для записи/агрегации time-series, downsampling, retention policies
- **Графы и связи** (топология карты, связи робот-зона-объект-задача) → **Neo4j** — нативный обход графов в Cypher, быстрые path queries
- **Оперативные данные** (текущее состояние роботов, кэш признаков для инференса) → **Redis** — in-memory, субмиллисекундный доступ, Streams для событий
- **Большие бинарные объекты** (кадры камер, 3D-облака точек, модели) → **MinIO** — S3-совместимый API, версионирование, lifecycle, presigned URLs
- **Структурированные бизнес-данные** (пользователи, роботы, задачи, аудит) → **PostgreSQL** — ACID-транзакции, ORM, миграции, сложные запросы

## Потоки данных

### Запись (Ingest)

1. **Телеметрия робота** → MQTT → Bridge → InfluxDB (через influxdb3-python, batch write с WriteOptions)
2. **Кадры камер** → Edge AI Proxy → MinIO (fput_object с metadata) → метаданные в PostgreSQL / InfluxDB
3. **Результаты инференса** → Orchestrator → PostgreSQL (задача + результат) + Neo4j (граф связей) + Redis (кэш для Dashboard)
4. **Состояние роботов** → MQTT retained → Redis Hash (`robot:{id}:state`) с TTL
5. **Бизнес-события** → RabbitMQ → Celery worker → PostgreSQL (audit_logs) + InfluxDB (метрики)

### Чтение (Query)

1. **Dashboard** → Redis (кэш текущего состояния) → если cache miss → PostgreSQL / InfluxDB
2. **Инференс** → Redis Feature Store (агрегированные признаки) + MinIO (модели для Triton/vLLM)
3. **Аналитика** → InfluxDB (SQL/InfluxQL через Arrow Flight) → pandas DataFrame для агрегатов
4. **Навигация** → Neo4j (Cypher запросы: ближайшая зарядная станция, маршрут через зоны)
5. **API запросы** → PostgreSQL (через SQLAlchemy ORM) с Redis-кэшированием

## Политики хранения

- **TTL для временных рядов** (InfluxDB): горячие данные 7 дней → агрегаты 30 дней → часовые агрегаты 1 год
- **TTL для кэшей** (Redis): 30s для телеметрии, 5m для состояний, без TTL для конфигурации
- **Retention для TimeSeries** (Redis): настраиваемый retention_msecs для каждого ключа
- **Lifecycle для объектов** (MinIO): transition в GLACIER через 30 дней, expiration через 365 дней
- **Версионирование** (MinIO): объектное версионирование для моделей и метаданных, возможность отката
- **WAL-бэкапы** (PostgreSQL): непрерывная WAL-репликация, регулярные бэкапы на MinIO
- **Snapshot Neo4j**: регулярные snapshot-бэкапы графов

---

## Интеграция

- API Gateway и Orchestrator читают/пишут данные через абстрактные репозитории (Repository Pattern)
- Batch-джобы (Celery) для ETL и подготовки данных для обучения
- Все клиенты поддерживают async/await (asyncio) для неблокирующей работы в FastAPI
- Единая точка мониторинга: Prometheus exporters для всех хранилищ → Grafana dashboards
