# Топики и маршрутизация сообщений

## Стратегия топиков MQTT

### Иерархический формат

Топики MQTT организованы иерархически через `/`. Формат топиков в AgentsSwarm:

`agentswarm/{tenant}/{robot_id}/{component}/{channel}`

| Уровень | Описание | Примеры значений |
|---------|----------|------------------|
| agentswarm | Корневой namespace системы | Фиксированный префикс |
| {tenant} | Идентификатор организации (мульти-тенантность) | companyA, factory_02 |
| {robot_id} | Уникальный идентификатор робота | robot_001, arm_lab_03 |
| {component} | Компонент робота или тип данных | camera, telemetry, cmd, status, inference |
| {channel} | Конкретный канал или действие | image_meta, pose, exec, result, lwt |

### Примеры топиков

| Топик | Направление | QoS | Описание |
|-------|-------------|-----|----------|
| `agentswarm/companyA/robot_001/telemetry/pose` | Robot → Cloud | 0 | Позиция робота (высокая частота) |
| `agentswarm/companyA/robot_001/telemetry/battery` | Robot → Cloud | 1 | Уровень заряда батареи |
| `agentswarm/companyA/robot_001/camera/image_meta` | Robot → Cloud | 1 | Метаданные кадра + ссылка MinIO |
| `agentswarm/companyA/robot_001/cmd/exec` | Cloud → Robot | 1 | Команда на выполнение задачи |
| `agentswarm/companyA/robot_001/cmd/estop` | Cloud → Robot | 2 | Аварийная остановка |
| `agentswarm/companyA/robot_001/cmd/ack` | Robot → Cloud | 1 | Подтверждение выполнения команды |
| `agentswarm/companyA/robot_001/status/online` | Robot → Cloud | 1 + retain | Текущий статус робота |
| `agentswarm/companyA/robot_001/status/lwt` | Broker → Cloud | 1 + retain | LWT при аварийном отключении |
| `agentswarm/companyA/robot_001/inference/result` | Robot → Cloud | 1 | Результат Edge-инференса |
| `agentswarm/companyA/robot_001/config/update` | Cloud → Robot | 1 | Обновление конфигурации |

## Wildcard-подписки MQTT

### Single-level wildcard `+`

Заменяет ровно один уровень иерархии. Применение:

| Подписка | Что получает |
|----------|-------------|
| `agentswarm/companyA/+/telemetry/pose` | Позиции **всех** роботов компании A |
| `agentswarm/companyA/+/status/online` | Статус **всех** роботов компании A |
| `agentswarm/+/robot_001/cmd/+` | Все команды роботу 001 от **любого** тенанта |
| `agentswarm/companyA/+/camera/+` | Все камерные данные **всех** роботов компании A |

### Multi-level wildcard `#`

Заменяет ноль или более уровней. Может стоять только в конце подписки:

| Подписка | Что получает |
|----------|-------------|
| `agentswarm/companyA/robot_001/#` | **Все** сообщения робота 001 |
| `agentswarm/companyA/#` | **Все** сообщения **всех** роботов компании A |
| `agentswarm/companyA/+/telemetry/#` | **Вся** телеметрия **всех** роботов компании A |
| `#` | **Все** сообщения системы (только для отладки!) |

### Правила применения

- Wildcard используются **только** в подписках, **не** в публикациях
- `+` должен занимать целый уровень: `agentswarm/comp+/robot_001` — **невалидно**
- `#` может стоять только в конце: `agentswarm/#/telemetry` — **невалидно**
- Утилита topic_matches_sub позволяет проверить, соответствует ли конкретный топик шаблону подписки

## Маршрутизация RabbitMQ (Routing Keys)

### Формат Routing Key

Routing key в RabbitMQ — строка слов, разделённых точками. Формат в AgentsSwarm:

`{domain}.{service}.{entity}.{action}`

| Уровень | Описание | Примеры значений |
|---------|----------|------------------|
| {domain} | Домен (robot, inference, orchestrator, alert, system) | robot, inference |
| {service} | Сервис-источник или тип ресурса | telemetry, triton, vllm, task |
| {entity} | Конкретная сущность или идентификатор | robot_001, model_yolo, task_abc |
| {action} | Действие или событие | created, completed, failed, updated |

### Примеры Routing Keys и Exchange'ов

| Exchange | Тип | Routing Key / Binding | Описание |
|----------|-----|----------------------|----------|
| `robot.events` | topic | `robot.telemetry.robot_001.pose` | Телеметрия конкретного робота |
| `robot.events` | topic | `robot.telemetry.*.pose` | Позиции всех роботов (подписка) |
| `robot.events` | topic | `robot.status.#` | Все статусные события роботов |
| `inference.events` | topic | `inference.triton.*.completed` | Завершённые инференсы Triton |
| `inference.events` | topic | `inference.vllm.*.result` | Результаты vLLM |
| `task.events` | topic | `task.*.robot_001.#` | Все события задач робота 001 |
| `system.broadcast` | fanout | (игнорируется) | Системные уведомления всем сервисам |
| `commands.direct` | direct | `gateway_service` | Прямая отправка в очередь Gateway |
| `alerts` | topic | `alert.critical.#` | Все критические алерты |
| `dlx.main` | fanout | (игнорируется) | Dead Letter Exchange для ошибок |

### Wildcard в Topic Exchange RabbitMQ

В отличие от MQTT, RabbitMQ использует точку `.` как разделитель и другие wildcard-символы:

| Символ | Значение | Пример binding_key | Что получает |
|--------|----------|---------------------|-------------|
| `*` | Ровно одно слово | `robot.*.completed` | `robot.task_abc.completed` ✅ / `robot.task.sub.completed` ❌ |
| `#` | Ноль или более слов | `robot.#` | `robot` ✅ / `robot.telemetry.pose` ✅ |

Сравнение wildcard MQTT vs RabbitMQ:

| Характеристика | MQTT | RabbitMQ Topic Exchange |
|----------------|------|------------------------|
| Разделитель уровней | `/` | `.` |
| Single-level wildcard | `+` | `*` |
| Multi-level wildcard | `#` | `#` |
| Используется в | Подписках (subscribe) | Binding keys |

## Bridge: MQTT ↔ RabbitMQ

### Принцип работы

Router/Bridge — компонент, который связывает MQTT-пространство (роботы) с RabbitMQ-пространством (внутренние сервисы). Подписывается на MQTT-топики через wildcard и переводит сообщения в RabbitMQ exchange'ы с соответствующими routing keys, и наоборот.

### Правила маппинга

| Направление | MQTT Топик | RabbitMQ Exchange | Routing Key |
|-------------|-----------|-------------------|-------------|
| Robot → Cloud | `agentswarm/{tenant}/{robot_id}/telemetry/{type}` | `robot.events` (topic) | `robot.telemetry.{robot_id}.{type}` |
| Robot → Cloud | `agentswarm/{tenant}/{robot_id}/camera/image_meta` | `robot.events` (topic) | `robot.camera.{robot_id}.image_meta` |
| Robot → Cloud | `agentswarm/{tenant}/{robot_id}/status/*` | `robot.events` (topic) | `robot.status.{robot_id}.*` |
| Robot → Cloud | `agentswarm/{tenant}/{robot_id}/inference/result` | `inference.events` (topic) | `inference.edge.{robot_id}.result` |
| Cloud → Robot | — | `robot.commands` (topic) `robot.cmd.{robot_id}.*` | → `agentswarm/{tenant}/{robot_id}/cmd/*` |

### Правила маршрутизации

- **Малые payloads** (телеметрия, статус, команды, ack) — передаются напрямую в теле MQTT-сообщения (JSON, Protobuf)
- **Крупные данные** (изображения, 3D-облака точек, видео) — сохраняются в MinIO (S3-совместимый API), в MQTT/RabbitMQ передаётся JSON с метаданными и ссылкой `minio://{bucket}/{object_key}`
- **Bridge переводит** MQTT → RabbitMQ только для сообщений, требующих внутренней обработки (инференс, логирование, агрегация)
- **Фильтрация**: Bridge не пересылает высокочастотную телеметрию QoS 0 (обрабатывается напрямую подписчиками MQTT — InfluxDB writer)

## QoS и гарантии доставки

### Выбор QoS по семантике топика

Каждому шаблону топика назначен уровень QoS по умолчанию (может быть переопределён через конфигурацию):

| Шаблон топика | QoS | Retain | Обоснование |
|---------------|-----|--------|-------------|
| `*/telemetry/*` | 0 | Нет | Высокая частота, потеря одного значения некритична |
| `*/camera/*` | 1 | Нет | Ссылки на MinIO должны быть доставлены |
| `*/cmd/exec` | 1 | Нет | Команды должны быть доставлены |
| `*/cmd/estop` | 2 | Нет | Аварийная остановка — ровно одно выполнение |
| `*/cmd/ack` | 1 | Нет | Подтверждения должны быть доставлены |
| `*/status/online` | 1 | Да | Новый подписчик видит текущий статус |
| `*/status/lwt` | 1 | Да | LWT всегда доступен |
| `*/config/*` | 1 | Да | Конфигурация доступна при переподключении |

### LWT конфигурация

Каждый робот при подключении регистрирует LWT:

- **Топик**: `agentswarm/{tenant}/{robot_id}/status/lwt`
- **Payload**: JSON — код состояния (`disconnected_unexpected`), последняя известная позиция, timestamp, battery_level
- **QoS**: 1
- **Retain**: True

При **штатном** отключении робот публикует явное сообщение в `*/status/online` с payload `{"status": "offline", "reason": "graceful_shutdown"}` перед вызовом disconnect.

## ACL и безопасность

### Аутентификация

- Каждый робот имеет **mTLS-сертификат** (X.509) — идентификация на уровне TLS handshake
- Дополнительно: **JWT-токен** с claims (tenant_id, robot_id, role) для авторизации
- Dashboard-клиенты: JWT-аутентификация через WebSocket
- Внутренние сервисы: отдельные credentials с расширенными правами

### ACL-политики

ACL ограничивает доступ к топикам на уровне publish и subscribe:

| Роль | Publish | Subscribe |
|------|---------|-----------|
| Robot (robot_001) | `agentswarm/{tenant}/robot_001/telemetry/#`, `agentswarm/{tenant}/robot_001/status/#`, `agentswarm/{tenant}/robot_001/cmd/ack`, `agentswarm/{tenant}/robot_001/inference/result` | `agentswarm/{tenant}/robot_001/cmd/#`, `agentswarm/{tenant}/robot_001/config/#` |
| Orchestrator | `agentswarm/{tenant}/+/cmd/#`, `agentswarm/{tenant}/+/config/#` | `agentswarm/{tenant}/#` |
| Dashboard | — | `agentswarm/{tenant}/#` (read-only) |
| Bridge Service | `agentswarm/#` | `agentswarm/#` (полный доступ для маршрутизации) |
| Admin | `agentswarm/#` | `agentswarm/#` |

### Административные топики

- Namespace: `$SYS/agentswarm/admin/{action}` — системные команды (перезагрузка конфигурации, обновление ACL)
- Доступ: только роль Admin с повышенной аутентификацией (mTLS + JWT с admin-scope)
- Аудит: все операции логируются в отдельную очередь RabbitMQ для audit trail
