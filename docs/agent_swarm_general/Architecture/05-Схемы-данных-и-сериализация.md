# Схемы данных и сериализация

## Форматы сериализации

| Контекст | Формат | Обоснование |
|----------|--------|-------------|
| MQTT (робот ↔ облако) | MessagePack или Protobuf | Компактность, низкий оверхед на Edge |
| gRPC (сервис ↔ сервис) | Protobuf | Типизация, кодогенерация, эффективность |
| WebSocket (шлюз → фронтенд) | JSON | Простота парсинга в браузере |
| WebSocket (бинарные данные) | Binary (raw bytes) | Для передачи изображений и 3D-данных |
| REST API | JSON | Универсальность |
| Redis | JSON или MessagePack | В зависимости от требований к скорости |
| PostgreSQL | Реляционная схема + JSONB | Структурированные данные с гибкими полями |

## Protobuf-схемы

### Телеметрия робота

Описывает структуру данных, отправляемых роботом в облако.

- **RobotTelemetry** — корневое сообщение, содержащее:
  - `robot_id` (строка) — уникальный идентификатор робота
  - `timestamp` (строка, ISO 8601) — временная метка
  - `status` (перечисление RobotStatus) — текущее состояние робота: IDLE, MOVING, EXECUTING_TASK, ERROR, CHARGING, OFFLINE
  - `position` (Position) — текущая позиция
  - `sensors` (карта строка → SensorData) — данные сенсоров по имени
  - `events` (список Event) — события, произошедшие с момента предыдущей отправки

- **Position** — позиция в пространстве:
  - `x`, `y`, `z` (float) — координаты в метрах
  - `orientation_x`, `orientation_y`, `orientation_z`, `orientation_w` (float) — кватернион ориентации
  - `frame_id` (строка) — система координат (например, `map`, `odom`)

- **SensorData** — данные одного сенсора:
  - `sensor_type` (строка) — тип сенсора (lidar, camera, imu, battery)
  - `timestamp` (строка) — временная метка измерения
  - `values` (карта строка → float) — числовые значения
  - `raw_data` (байты) — сырые бинарные данные (при необходимости)

### Команды управления

- **Command** — команда, отправляемая роботу:
  - `command_id` (строка, UUID) — уникальный идентификатор команды
  - `robot_id` (строка) — целевой робот
  - `target_component` (строка) — компонент робота: `navigation`, `arm`, `camera`, `all`
  - `type` (перечисление CommandType) — тип команды: MOVE_TO, PICK_UP, PUT_DOWN, SCAN, STOP, EMERGENCY_STOP, UPDATE_CONFIG, UPDATE_MODEL
  - `payload` (байты) — JSON или бинарные параметры команды
  - `priority` (целое число) — приоритет от 1 (низкий) до 100 (экстренный)
  - `retain` (булево) — сохранять ли команду в MQTT как retained message
  - `timeout_seconds` (целое число) — таймаут ожидания выполнения

- **CommandResponse** — ответ на команду:
  - `command_id` (строка) — идентификатор исходной команды
  - `success` (булево) — успешность
  - `message_id` (строка) — идентификатор MQTT-сообщения
  - `error_message` (строка) — описание ошибки (если есть)

### AI Inference

- **ImageRequest** — запрос к Triton:
  - `image_data` (байты) — сырые данные изображения
  - `model_name` (строка) — имя модели (`yolov8`, `deepsort`, `ensemble`)
  - `robot_id` (строка) — от какого робота изображение
  - `timestamp` (строка) — когда сделан снимок

- **DetectionResponse** — ответ от Triton:
  - `detections` (список Detection) — обнаруженные объекты
  - `processing_time_ms` (float) — время обработки
  - `model_version` (строка) — версия модели

- **Detection** — один обнаруженный объект:
  - `class_name` (строка) — класс объекта
  - `confidence` (float) — уверенность [0, 1]
  - `bbox` (BoundingBox) — ограничивающий прямоугольник
  - `track_id` (целое число, опционально) — идентификатор трекинга

- **BoundingBox**:
  - `x_min`, `y_min`, `x_max`, `y_max` (float) — координаты в пикселях

### gRPC-сервисы

- **RobotControl** — сервис управления роботами:
  - `SendCommand(CommandRequest) → CommandResponse` — отправка одиночной команды
  - `GetRobotStatus(RobotId) → RobotStatus` — получение текущего статуса
  - `StreamTelemetry(RobotId) → stream TelemetryData` — потоковая телеметрия
  - `StreamCommands(stream Command) → stream CommandAck` — двунаправленный поток команд

- **TritonInference** — сервис детекции:
  - `Detect(ImageRequest) → DetectionResponse` — детекция объектов
  - `StreamDetections(stream ImageRequest) → stream DetectionResponse` — потоковая детекция

- **VLLMService** — сервис языковых моделей:
  - `Generate(GenerateRequest) → GenerateResponse` — генерация текста
  - `StreamGenerate(GenerateRequest) → stream TokenResponse` — потоковая генерация
  - `AnalyzeImage(VisionRequest) → AnalysisResponse` — мультимодальный анализ

## Схемы MQTT-сообщений

### Телеметрия позиции
Топик: `telemetry/{robot_id}/pose`

Поля:
- `robot_id` (строка)
- `timestamp` (строка, ISO 8601)
- `x`, `y`, `z` (float, метры)
- `qx`, `qy`, `qz`, `qw` (float, кватернион)
- `linear_velocity` (float, м/с)
- `angular_velocity` (float, рад/с)

### Телеметрия батареи
Топик: `telemetry/{robot_id}/battery`

Поля:
- `robot_id` (строка)
- `timestamp` (строка)
- `level` (float, 0–100, проценты)
- `voltage` (float, вольты)
- `current` (float, амперы)
- `charging` (булево)
- `estimated_runtime_minutes` (целое число)

### Команда действия
Топик: `commands/{robot_id}/action`

Поля:
- `command_id` (строка, UUID)
- `type` (строка) — тип команды
- `parameters` (объект) — параметры, зависящие от типа
- `priority` (целое число)
- `timeout_seconds` (целое число)
- `source` (строка) — кто отправил (orchestrator, user)
- `timestamp` (строка)

### Экстренное событие
Топик: `events/{robot_id}/emergency`

Поля:
- `event_id` (строка, UUID)
- `robot_id` (строка)
- `severity` (строка) — `critical`, `warning`
- `type` (строка) — `obstacle_detected`, `person_detected`, `hardware_failure`, `low_battery_critical`
- `message` (строка) — описание
- `position` (объект) — координаты робота на момент события
- `action_taken` (строка) — действие, предпринятое локально (`emergency_stop`, `reroute`)
- `timestamp` (строка)

### Подтверждение команды
Топик: `ack/{robot_id}/{command_id}`

Поля:
- `command_id` (строка)
- `status` (строка) — `received`, `executing`, `completed`, `failed`
- `progress` (float, 0–100, проценты)
- `error` (строка, опционально) — описание ошибки
- `timestamp` (строка)

## Схемы WebSocket-сообщений

### От клиента к серверу

**Сообщение чата:**
- `type`: `chat_message`
- `payload.text` (строка) — текст команды
- `payload.user_id` (строка)
- `message_id` (строка, UUID)

**Подписка на робота:**
- `type`: `subscribe_robot`
- `payload.robot_id` (строка)

**Запрос статуса роя:**
- `type`: `request_swarm_status`

### От сервера к клиенту

**Обновление состояния:**
- `type`: `state_update`
- `data.step` (строка) — текущий шаг обработки (analyzing, planning, executing)
- `data.details` (объект) — детали текущего шага

**Ответ чата (потоковый):**
- `type`: `chat_response`
- `data.text` (строка) — фрагмент ответа
- `data.is_final` (булево)
- `data.plan` (объект, опционально) — сгенерированный план

**Действие:**
- `type`: `action`
- `data.robot_id` (строка)
- `data.task` (объект)
- `data.status` (строка)

**Телеметрия:**
- `type`: `telemetry`
- `data.robot_id` (строка)
- `data.position` (объект)
- `data.battery` (float)
- `data.status` (строка)

## Схемы баз данных

### PostgreSQL

**Таблица robots** — реестр роботов:
- `id` (UUID, PK)
- `name` (строка)
- `type` (строка) — тип робота (ground, drone, manipulator)
- `capabilities` (JSONB) — возможности (has_arm, has_camera, max_speed)
- `status` (строка)
- `registered_at` (timestamp)
- `last_seen_at` (timestamp)

**Таблица tasks** — задачи:
- `id` (UUID, PK)
- `parent_task_id` (UUID, FK, nullable) — родительская задача
- `robot_id` (UUID, FK, nullable) — назначенный робот
- `type` (строка)
- `parameters` (JSONB)
- `status` (строка) — pending, assigned, executing, completed, failed
- `priority` (integer)
- `created_by` (UUID, FK) — пользователь
- `created_at`, `started_at`, `completed_at` (timestamp)
- `result` (JSONB)

**Таблица users** — пользователи:
- `id` (UUID, PK)
- `username` (строка)
- `role` (строка) — operator, admin, viewer
- `created_at` (timestamp)

**Таблица incidents** — инциденты:
- `id` (UUID, PK)
- `robot_id` (UUID, FK)
- `severity` (строка)
- `type` (строка)
- `description` (текст)
- `position` (JSONB)
- `action_taken` (строка)
- `resolved` (булево)
- `occurred_at` (timestamp)

### InfluxDB

**Measurement: robot_telemetry**
- Tags: `robot_id`, `sensor_type`
- Fields: `x`, `y`, `z`, `qx`, `qy`, `qz`, `qw`, `velocity`, `battery_level`
- Timestamp: nanosecond precision

**Retention Policies:**
- `raw_data`: 7 дней (полная детализация)
- `aggregated_1m`: 90 дней (агрегация по 1 минуте)
- `aggregated_1h`: 1 год (агрегация по 1 часу)

### Neo4j

**Узлы:**
- `(:Robot {id, name, type, status})` — робот
- `(:Object {id, class, confidence, first_seen, last_seen})` — обнаруженный объект
- `(:Location {id, x, y, z, name})` — именованная локация
- `(:Task {id, type, status})` — задача

**Связи:**
- `(:Robot)-[:DETECTED]->(:Object)` — робот обнаружил объект
- `(:Object)-[:LOCATED_AT]->(:Location)` — объект находится в локации
- `(:Robot)-[:ASSIGNED_TO]->(:Task)` — робот назначен на задачу
- `(:Robot)-[:NEAR]->(:Robot)` — роботы находятся рядом
- `(:Task)-[:DEPENDS_ON]->(:Task)` — зависимость между задачами

### Redis (ключи)

| Шаблон ключа | Тип | TTL | Описание |
|--------------|-----|-----|----------|
| `robot:{id}:latest` | Hash | 5 мин | Последнее состояние робота |
| `robot:{id}:detections:latest` | String (JSON) | 30 сек | Последние детекции |
| `plan:{id}` | Hash | 1 час | Текущий план |
| `command:{id}` | String (JSON) | timeout | Отслеживание команды |
| `session:{user_id}` | Hash | 30 мин | Сессия пользователя |
| `feature:{robot_id}:{ts}` | Hash + Vector | 24 часа | Фичи для векторного поиска |
