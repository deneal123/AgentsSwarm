# SmolVLA — Cloud-версия

## Характеристики

| Параметр | Значение |
|----------|---------|
| HuggingFace ID | `lerobot/smolvla_base` (предобученная) |
| Параметры | ~450 миллионов |
| Vision Encoder | SigLIP-base (86M) |
| Language Encoder | SmolLM-based (встроенный) |
| Action Decoder | Transformer + Flow Matching Head |
| Вход (изображение) | Несколько ракурсов камер (фронт, бок, запястье) |
| Вход (текст) | Инструкция до 256 токенов |
| Вход (проприоцепция) | Текущее состояние суставов робота |
| Выход | Chunk из 10–50 действий (настраиваемый `actions_per_chunk`) |
| Латентность | ~50 мс (A100), ~120 мс (A10G) |
| GPU Memory | ~2 GB (BF16) |
| Точность | BF16 |

---

## Развёртывание

### На GPU-сервере

Cloud-версия SmolVLA развёртывается в составе AI-кластера:

- Отдельный контейнер с PyTorch или ONNX Runtime
- Доступна через gRPC-интерфейс (порт 50055)
- Может быть загружена на тот же GPU, что и Triton/vLLM (при наличии свободной памяти ~2GB)
- Поддерживает dynamic batching для параллельной обработки запросов от нескольких роботов

### Альтернатива: Triton Backend

SmolVLA может быть развёрнута как модель внутри Triton Inference Server через Python Backend или ONNX Backend. Это упрощает управление моделями и унифицирует мониторинг, но добавляет overhead Triton (~5 мс).

## Inference Pipeline

### Этапы обработки

1. **Приём запроса**: gRPC-сервер получает изображение(я) + текстовую инструкцию + (опционально) текущее состояние робота (позиция, углы суставов)
2. **Предобработка изображения**: ресайз до 224×224, нормализация, конвертация в тензор
3. **Токенизация текста**: инструкция токенизируется встроенным токенизатором
4. **Кодирование визуальных признаков**: SigLIP кодирует изображение(я) в визуальные эмбеддинги
5. **Кодирование текста**: языковой кодировщик создаёт текстовые эмбеддинги
6. **Cross-modal Fusion**: трансформерные слои комбинируют визуальные и текстовые признаки через cross-attention
7. **Flow Matching Decoding**: декодер генерирует chunk действий через итеративный процесс flow matching (обычно 10 шагов деnoising)
8. **Постобработка**: масштабирование действий из нормализованного пространства в реальные единицы (метры, радианы)
9. **Отправка результата**: chunk действий возвращается через gRPC

### Формат действия (7-DoF)

Каждое действие в chunk представляет собой вектор из 7 компонент:

| Компонент | Описание | Диапазон |
|-----------|----------|----------|
| x | Линейное перемещение по оси X | -1.0 … +1.0 (м) |
| y | Линейное перемещение по оси Y | -1.0 … +1.0 (м) |
| z | Линейное перемещение по оси Z | -1.0 … +1.0 (м) |
| rx | Вращение вокруг оси X (roll) | -π … +π (рад) |
| ry | Вращение вокруг оси Y (pitch) | -π … +π (рад) |
| rz | Вращение вокруг оси Z (yaw) | -π … +π (рад) |
| gripper | Состояние захвата | 0.0 (открыт) … 1.0 (закрыт) |

### Action Chunking

Модель генерирует chunk действий за один inference. Размер chunk настраивается параметром `actions_per_chunk` (типичные значения: 10–50):

- Робот выполняет действия последовательно (каждые 20–50 мс в зависимости от частоты control loop)
- Пока робот выполняет текущий chunk, облако вычисляет следующий
- Перекрывающиеся части chunk'ов агрегируются функцией взвешенного среднего (`weighted_average`) для плавности
- При существенном расхождении между ожидаемым и фактическим состоянием — текущий chunk прерывается, запрашивается новый
- Больший `actions_per_chunk` снижает вероятность пустой очереди действий, но может накапливать ошибку при длинных горизонтах

## Асинхронный Inference (PolicyServer / RobotClient)

### Архитектура

Cloud-версия использует асинхронную схему LeRobot для минимизации задержек, полностью устраняя простои робота (idle frames):

**PolicyServer** — серверный процесс на GPU-сервере:
- Инициализируется как пустой контейнер, конфигурируется при первом подключении клиента
- Загружает SmolVLA (или X-VLA) и выполняет inference по мере поступления наблюдений
- Может обслуживать нескольких RobotClient по сети (один PolicyServer на GPU для нескольких роботов)
- Запуск: указываются только host и port, всё остальное определяется клиентом

**RobotClient** — клиентский процесс на стороне робота:
- Стримит наблюдения (изображения с камер, состояние суставов) на PolicyServer
- Получает action chunks и управляет исполнением действий через локальную очередь
- При заполненности очереди ниже порога `chunk_size_threshold` (по умолчанию 0.5) отправляет новое наблюдение на сервер
- Работает по сети (облако → робот) или локально (на одной машине)

### Ключевые параметры настройки

| Параметр | Значение | Влияние |
|----------|---------|---------|
| `actions_per_chunk` | 10–50 | Больше → стабильнее очередь, но менее точные долгосрочные действия |
| `chunk_size_threshold` | 0.5–0.6 | Выше → чаще запросы к серверу, лучше адаптивность; 0.0 → синхронный режим |
| `aggregate_fn_name` | `weighted_average` | Функция агрегации перекрывающихся chunk'ов |

### Параллельная обработка нескольких роботов

При управлении роем роботов cloud-версия обрабатывает запросы параллельно:

- Dynamic Batching: запросы от разных роботов группируются в батч
- Приоритизация: роботы в активной манипуляции приоритетнее роботов в навигации
- Load Balancing: при нескольких GPU-нодах запросы распределяются по нагрузке

## Интеграция с Orchestrator

### Запрос от Orchestrator

Orchestrator вызывает SmolVLA Cloud, когда:

- Робот получил задачу манипуляции (pick, place, assemble)
- Требуется сложное планирование физических действий
- Edge-версия не справилась (fallback)
- Нужна демонстрация для обучения edge-версии

### Контекст запроса

Orchestrator передаёт в SmolVLA:

- Текстовую инструкцию задачи
- Текущее изображение с камеры робота
- (Опционально) 2 предыдущих кадра для понимания динамики
- Текущее состояние робота (позиция манипулятора, углы суставов)
- Результаты Triton (bounding boxes целевых объектов) — для фокусировки внимания модели

### Ответ SmolVLA

- Chunk из 10 действий (7-DoF каждое)
- Confidence score (оценка уверенности модели в плане)
- Estimated completion: приблизительное число chunk'ов до завершения задачи
- Флаг task_complete: True, если модель считает задачу завершённой

## Мониторинг

### Метрики

| Метрика | Описание | Целевое значение |
|---------|----------|-----------------|
| smolvla_cloud_latency_p95 | Латентность inference | < 80 мс |
| smolvla_cloud_throughput | Запросов в секунду | > 50 |
| smolvla_cloud_batch_size_avg | Средний размер батча | 4–8 |
| smolvla_cloud_success_rate | Доля успешных задач | > 90% |
| smolvla_cloud_action_magnitude | Средняя величина действий | Мониторинг (аномалии) |

### Алерты

| Условие | Уровень | Действие |
|---------|---------|----------|
| Латентность > 150 мс (p95) | Warning | Проверить нагрузку GPU |
| Success rate < 80% | Critical | Проверить модель, откатить версию |
| Action magnitude > порог | Critical | Возможная генерация аномальных действий, остановить |
| Batch queue > 100 запросов | Warning | Масштабировать реплики |

## X-VLA Cloud — кросс-платформенная альтернатива

### Когда использовать X-VLA вместо SmolVLA

X-VLA (`lerobot/xvla-base`, 0.9B параметров) предпочтительнее SmolVLA для cloud-развёртывания, когда:

- **Гетерогенный рой**: в рое роботы разных типов (одноручные манипуляторы, бимануальные, мобильные), и нужна единая модель
- **Частое добавление новых роботов**: X-VLA адаптируется к новому типу робота через обучение Soft Prompts (1% параметров) за ~3000 шагов
- **Сложные задачи**: 0.9B параметров обеспечивают более высокое качество на задачах, требующих семантического понимания

### Action Modes

X-VLA использует систему **Action Modes** — реестр обработчиков пространства действий. Каждый Action Mode определяет:

- Размерность действия (dim_action)
- Функцию потерь (MSE для суставов, BCE для захвата)
- Пре-процессинг действий (обнуление, паддинг)
- Пост-процессинг предсказаний (sigmoid для захвата, тримминг)

Доступные Action Modes:

| Mode | Размерность | Описание |
|------|------------|----------|
| `ee6d` | 20 | End-effector с xyz, 6D rotation, gripper |
| `joint` | 14 | Joint-space с gripper |
| `so101_bimanual` | 20 (модель), 12 (реальный) | Бимануальный SO101 |
| `auto` | 20 (модель), авто (реальный) | Автоопределение по датасету — **рекомендуемый** |

Режим `auto` определяет реальную размерность действий из датасета, выполняет паддинг до 20D для совместимости с предобученной моделью, а при inference тримит обратно. Loss вычисляется только на реальных размерностях.

### Domain IDs

Каждой конфигурации «робот + камеры» присваивается уникальный Domain ID (0–29). Soft Prompts привязаны к Domain ID и кодируют специфику оборудования. При обучении Domain ID добавляется автоматически через `XVLAAddDomainIdProcessorStep`.

### Характеристики X-VLA Cloud

| Параметр | Значение |
|----------|---------|
| HuggingFace ID | `lerobot/xvla-base` |
| Параметры | ~900 миллионов |
| GPU Memory | ~4 ГБ (BF16) |
| Chunk Size | 32 действия |
| Denoising Steps | 10 (flow matching) |
| Domain IDs | До 30 |
| Soft Prompt Length | 32 эмбеддинга |
