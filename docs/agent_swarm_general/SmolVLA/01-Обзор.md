# SmolVLA — Обзор

## Назначение

SmolVLA (Small Vision-Language-Action model) — компактная мультимодальная модель, объединяющая понимание зрения и языка с генерацией действий для роботов. Является ключевым компонентом, связывающим восприятие окружающей среды с физическим действием робота.

---

## Что такое VLA

Vision-Language-Action (VLA) — класс моделей, которые принимают на вход визуальное наблюдение (изображение с камеры) и текстовую инструкцию, а на выходе генерируют конкретные действия для робота (координаты перемещения, углы суставов, команды захвата).

В отличие от классического подхода, где восприятие, планирование и управление — отдельные модули, VLA объединяет все три функции в единой нейронной сети.

---

## SmolVLA в экосистеме HuggingFace

SmolVLA разработана в рамках проекта HuggingFace LeRobot — открытой платформы для робототехнического AI. Базовая предобученная модель доступна как `lerobot/smolvla_base` на HuggingFace Hub. Модель оптимизирована для работы на edge-устройствах и является более компактной альтернативой таким моделям, как RT-2 или OpenVLA.

Параллельно с SmolVLA в экосистеме LeRobot доступна модель **X-VLA** (`lerobot/xvla-base`, 0.9B параметров) — более мощная кросс-платформенная VLA, способная работать с разными морфологиями роботов через механизм **Soft Prompts** (обучаемых эмбеддингов, кодирующих специфику конкретного робота).

| Параметр | SmolVLA (Cloud) | SmolVLA (Edge) | X-VLA |

## Архитектура модели

### Компоненты

1. **Vision Encoder**: извлекает визуальные признаки из изображения камеры. Используется компактная архитектура (SigLIP или DINOv2-small) для эффективного кодирования
2. **Language Encoder**: кодирует текстовую инструкцию. Используется компактный текстовый кодировщик, совместимый с основным трансформером
3. **Action Decoder**: на основе визуальных и текстовых эмбеддингов генерирует вектор действия. Использует Cross-Attention между модальностями и MLP-голову для предсказания действий

### Особенности архитектуры

- **Flow Matching**: SmolVLA использует Flow Matching для генерации действий — это позволяет моделировать сложные распределения действий (например, при наличии нескольких допустимых способов схватить объект). X-VLA также использует flow matching
- **Action Chunking**: модель генерирует не одно действие, а последовательность (chunk) из нескольких будущих действий. Размер chunk настраивается: от 10 до 50 действий (параметр `actions_per_chunk`). Это сглаживает траекторию и снижает частоту вызовов модели
- **Multi-Image Support**: модель принимает несколько ракурсов камер одновременно (фронтальная, боковая, запястная), что обеспечивает объёмное понимание сцены
- **Сенсомоторное состояние**: помимо визуального входа модель получает текущее состояние суставов робота (proprioception) для более точной генерации действий
- **Asynchronous Inference**: LeRobot предоставляет архитектуру PolicyServer / RobotClient для асинхронного inference — следующий chunk действий вычисляется параллельно с выполнением текущего, устраняя простои робота

### Soft Prompts (X-VLA)

X-VLA вводит концепцию **Soft Prompts** — обучаемых эмбеддингов, кодирующих специфику конкретного робота и конфигурации камер. Каждый тип робота в рое получает уникальный **Domain ID** (до 30), которому соответствует набор Soft Prompts. При адаптации к новому роботу обучаются только Soft Prompts (1% параметров, ~9M), а backbone остаётся замороженным. Это обеспечивает производительность, сопоставимую с полным дообучением, при затрате в ~300× меньше вычислительных ресурсов.

## Зона ответственности

### В облаке (Cloud)

- Генерация сложных последовательностей действий для манипуляции
- Планирование многошаговых физических задач
- Обработка нестандартных ситуаций, требующих рассуждения
- Генерация демонстраций для обучения edge-версии

### На edge (Edge)

- Реактивное управление манипулятором в реальном времени
- Базовые задачи: подбор, перемещение, размещение объектов
- Автономная работа при потере связи с облаком
- Коррекция движений на основе визуальной обратной связи

## Режимы работы

### Режим «Инструкция»

Модель получает текстовую инструкцию и текущее изображение, генерирует последовательность действий до завершения задачи.

Пример: инструкция «Возьми красный куб и поставь на синюю платформу» → модель генерирует серию действий: приближение к кубу, захват, подъём, перемещение, размещение, отпускание.

### Режим «Коррекция»

Модель получает текущее состояние + ожидаемое состояние + изображение и генерирует корректирующее действие. Используется, когда предыдущее действие выполнено не точно.

### Режим «Исследование»

Модель получает инструкцию общего характера («Осмотри объект», «Найди путь к двери») и генерирует действия для исследования окружения. Выход: последовательность наблюдений и перемещений.

## Сравнение с альтернативами

| Модель | Параметры | Латентность | Edge-совместимость | Кросс-платформенность | Открытая |
|--------|-----------|-------------|--------------------|-----------------------|----------|
| SmolVLA | 450M / 150M | 50–100 мс | Да | Нет (одна морфология) | Да |
| X-VLA | 900M | ~80 мс (A100) | Нет | Да (Soft Prompts, до 30 роботов) | Да |
| RT-2 (Google) | 55B | > 1 сек | Нет | Нет | Нет |
| OpenVLA | 7B | ~200 мс (A100) | Нет | Нет | Да |
| Octo | 93M | ~30 мс | Да | Частичная | Да |
| PI0 | ~3B | ~200 мс | Нет (14 ГБ GPU) | Частичная | Да |

SmolVLA выбрана как оптимальный баланс: достаточно мощная для сложных задач (450M > Octo), достаточно компактная для edge (150M на Jetson, всего ~2 ГБ GPU-памяти при inference), открытая и интегрируемая через LeRobot. X-VLA используется как дополнение для гетерогенных роёв с разными типами роботов.
