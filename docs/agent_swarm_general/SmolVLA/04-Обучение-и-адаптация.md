# SmolVLA — Обучение и адаптация

## Стратегия обучения SmolVLA

### Базовое обучение (Pre-training)

SmolVLA предварительно обучена на больших датасетах робототехнических демонстраций в рамках проекта LeRobot (HuggingFace). Базовая модель (`lerobot/smolvla_base`, 450M параметров) обладает общими навыками манипуляции: захват объектов различных форм и размеров, перемещение, размещение, базовая навигация.

### Дообучение SmolVLA (Fine-tuning)

Для адаптации к конкретным задачам и типам роботов платформы используется LeRobot Training Pipeline (CLI-утилита `lerobot-train`).

**Ключевые параметры дообучения:**

| Параметр | Рекомендуемое значение | Описание |
|----------|----------------------|----------|
| Базовая модель | `lerobot/smolvla_base` | HuggingFace ID предобученной модели |
| Датасет | HuggingFace repo_id | Датасет демонстраций в формате LeRobot Dataset |
| Batch Size | 64 | Размер батча (оптимально для A100) |
| Steps | 20 000 | Количество шагов обучения |
| Время обучения | ~4 часа на A100 | Полный цикл дообучения |
| Метод | Full Fine-tuning или LoRA | LoRA — для экономии ресурсов |

**Процесс:**

1. Подготовить датасет демонстраций в формате LeRobot Dataset и загрузить на HuggingFace Hub (или указать локальный путь)
2. Запустить обучение через `lerobot-train`, указав путь к базовой модели, идентификатор датасета, batch_size и количество шагов
3. Модель автоматически загружает веса, применяет нормализацию действий и обучается на демонстрациях
4. Checkpoints сохраняются периодически; лучший checkpoint определяется по validation loss

### Требования к датасету

Минимальный объём данных для качественного дообучения SmolVLA:

- **~50 эпизодов** (демонстраций) — минимально достаточный объём
- Рекомендуемая структура: **5 вариаций** начальных условий × **10 эпизодов** на каждую вариацию
- Вариации должны покрывать: разные позиции объектов, разное освещение, разные начальные конфигурации робота
- Каждый эпизод включает полное выполнение задачи от начала до конца

### LoRA-адаптация SmolVLA

Для экономии ресурсов рекомендуется LoRA (Low-Rank Adaptation):

- Дообучение только небольшого числа параметров (< 5% от общего числа)
- Быстрое дообучение (часы вместо дней)
- Малый размер адаптеров (несколько MB вместо полных весов модели)
- Возможность хранить множество адаптеров для разных задач
- Быстрое переключение между задачами (загрузка другого адаптера)

## Стратегия обучения X-VLA

### Двухфазный процесс обучения

X-VLA (`lerobot/xvla-base`, 0.9B параметров) использует принципиально другой подход к обучению:

#### Phase I — Кросс-платформенное предобучение

- Обучение на **290 000 эпизодов** из **7 робототехнических платформ** (различные манипуляторы, бимануальные роботы, мобильные платформы)
- VLM-энкодеры (vision + language) **не замораживаются** — позволяет адаптировать визуальное восприятие к робототехническим задачам
- VLM обучается с learning rate в **10 раз ниже** базового — предотвращает catastrophic forgetting претренированных знаний
- Precision: bfloat16
- Результат: универсальная модель, понимающая различные типы роботов

#### Phase II — Доменная адаптация через Soft Prompts

Ключевое преимущество X-VLA — адаптация к новому типу робота через **Soft Prompts** вместо полного fine-tuning:

| Параметр | Значение |
|----------|---------|
| Обучаемые параметры | ~9 миллионов (1% от общего числа) |
| Компоненты | Soft Prompt эмбеддинги (32 токена) + Action Head |
| Шаги обучения | ~3 000 |
| Время | ~1 час на A100 |
| Base model | Заморожена полностью |

**Механизм Soft Prompts:**

- Каждой конфигурации «робот + камеры» присваивается уникальный **Domain ID** (от 0 до 29)
- Domain ID индексирует набор обучаемых Soft Prompt эмбеддингов (32 эмбеддинга)
- Soft Prompts добавляются к входу модели и кодируют специфику конкретного оборудования
- При обучении Domain ID назначается автоматически через препроцессор `XVLAAddDomainIdProcessorStep`
- При добавлении нового типа робота — обучается только новый Soft Prompt, остальные остаются неизменными

### Action Modes в X-VLA

X-VLA использует систему **Action Modes** — реестр обработчиков пространства действий, обеспечивающий кросс-платформенность:

| Mode | Размерность модели | Реальная размерность | Описание |
|------|-------------------|---------------------|----------|
| `ee6d` | 20 | 20 | End-effector с xyz, 6D rotation, gripper |
| `joint` | 14 | 14 | Joint-space с gripper |
| `so101_bimanual` | 20 | 12 | Бимануальный SO101 |
| `auto` | 20 | определяется из данных | **Рекомендуемый** — автоопределение из датасета |

Режим `auto`:

- Автоматически определяет реальную размерность действий из датасета
- Выполняет паддинг до 20D для совместимости с предобученной моделью
- При inference тримит предсказание обратно до реальной размерности
- Loss вычисляется только на реальных размерностях (паддинг-позиции игнорируются)
- Функция потерь: MSE для непрерывных действий, BCE для дискретных (gripper)

### Сравнение подходов к адаптации

| Критерий | SmolVLA Fine-tune | X-VLA Soft Prompts |
|----------|------------------|-------------------|
| Обучаемые параметры | 450M (full) или ~20M (LoRA) | ~9M (1%) |
| Шаги обучения | 20 000 | 3 000 |
| Время на A100 | ~4 часа | ~1 час |
| Минимум эпизодов | ~50 | ~50 |
| Поддержка multi-robot | Отдельная модель/адаптер | Единая модель + Domain IDs |
| Качество (один робот) | Высокое | Высокое |
| Кросс-платформенность | Нет | Да (до 30 платформ) |
| Рекомендация | Один тип робота | Гетерогенный рой |

## Сбор демонстраций

### Телеоперация

Основной способ сбора демонстраций — телеоперация робота оператором:

1. Оператор управляет роботом через интерфейс управления (джойстик, 3D-мышь, VR-контроллер)
2. Система записывает: изображения с камеры, состояние робота (суставы, позиция), действия оператора, текстовую аннотацию задачи
3. Данные сохраняются в формате LeRobot Dataset

### Автоматический сбор

После начального обучения модель может генерировать дополнительные демонстрации:

- Модель выполняет задачу, результат оценивается (успех/неудача)
- Успешные выполнения добавляются в датасет
- Неудачные анализируются для улучшения

### Формат датасета LeRobot

LeRobot Dataset — стандартный формат HuggingFace для робототехнических данных. Датасеты могут храниться на HuggingFace Hub или локально.

| Поле | Описание |
|------|----------|
| observation.image | Изображение с камеры (224×224×3), до 3 камер |
| observation.state | Сенсомоторное состояние робота (позиции суставов) |
| action | Действие (вектор, размерность зависит от робота) |
| language_instruction | Текстовая инструкция задачи |
| episode_index | Индекс эпизода |
| frame_index | Индекс кадра внутри эпизода |
| timestamp | Временная метка |
| next.done | Флаг завершения эпизода |

### Environment Processors (препроцессоры окружения)

LeRobot использует систему **Environment Processors** для разделения задач предобработки данных:

- **Environment-specific процессоры**: зависят от конкретной среды/робота. Пример: преобразование пространства наблюдений, нормализация суставов, преобразование систем координат
- **Policy-specific процессоры**: зависят от политики (модели). Пример: `XVLAAddDomainIdProcessorStep` добавляет Domain ID для X-VLA; resize изображений для входа модели

Процессоры объединяются в цепочку (`EnvProcessorPipeline`) и применяются автоматически при сборе данных, обучении и inference.

**Значение для AgentsSwarm**: для каждого типа робота в рое создаётся свой env-specific процессор (нормализация суставов, преобразование координат), а policy-specific процессоры остаются едиными для SmolVLA/X-VLA. Это позволяет добавлять новые типы роботов без изменения модели.

## Пайплайн обучения

### Этапы

1. **Подготовка данных**: загрузка демонстраций из MinIO, валидация, нормализация
2. **Аугментация**: случайные преобразования изображений (яркость, контраст, crop, цветовые искажения) для робастности
3. **Обучение LoRA-адаптеров**: дообучение на целевом датасете с frozen base model
4. **Валидация**: оценка на held-out демонстрациях
5. **Конвертация Edge**: создание edge-версии адаптера (pruning + quantization)
6. **Тестирование**: запуск в симуляторе или на реальном роботе
7. **Деплой**: загрузка адаптера в MinIO, OTA-обновление на роботах

### Гиперпараметры обучения SmolVLA

| Параметр | Значение | Обоснование |
|----------|---------|-------------|
| Базовая модель | `lerobot/smolvla_base` | Предобученная модель 450M |
| Batch Size | 64 | Оптимально для A100 80GB |
| Steps | 20 000 | До конвергенции |
| Learning Rate | 1e-4 | Стандарт для fine-tuning |
| LoRA Rank (если LoRA) | 16–64 | Компромисс между ёмкостью и размером |
| LoRA Alpha | 32 | Масштабирование LoRA |
| Weight Decay | 0.01 | Регуляризация |
| Warmup Steps | 500 | Стабилизация начала обучения |
| Gradient Clipping | 1.0 | Предотвращение взрыва градиентов |
| Время обучения | ~4 часа на A100 | Полный цикл |

### Гиперпараметры обучения X-VLA

| Параметр | Phase I (Pretrain) | Phase II (Adapt) |
|----------|-------------------|-----------------|
| Базовая модель | — | `lerobot/xvla-base` |
| Обучаемые компоненты | Все | Soft Prompts + Action Head |
| Precision | bfloat16 | bfloat16 |
| VLM Encoders | Не заморожены (LR × 0.1) | Заморожены |
| Steps | Полный цикл | ~3 000 |
| Датасет | 290K эпизодов, 7 платформ | Целевой датасет |

### Метрики обучения

| Метрика | Описание | Целевое значение |
|---------|----------|-----------------|
| Train Loss | Ошибка на обучающей выборке | Монотонное убывание |
| Val Loss | Ошибка на валидационной выборке | Минимум (early stopping) |
| Action MSE | Среднеквадратичная ошибка действий | < 0.01 |
| Success Rate (sim) | Доля успешных выполнений в симуляторе | > 85% |
| Success Rate (real) | Доля успешных выполнений на реальном роботе | > 75% |

## Адаптация к новым задачам

### Процедура добавления новой задачи (SmolVLA)

1. **Определение задачи**: текстовое описание, критерии успеха, ограничения безопасности
2. **Сбор демонстраций**: минимум ~50 эпизодов (5 вариаций × 10 повторений). Сбор через `lerobot-record` или телеоперацию
3. **Загрузка датасета**: публикация на HuggingFace Hub в формате LeRobot Dataset
4. **Обучение**: запуск `lerobot-train` с указанием `lerobot/smolvla_base` и датасета. Batch size 64, 20 000 шагов, ~4 часа на A100
5. **Оценка в симуляции**: тестирование в IsaacLab Arena или через `lerobot-record --eval` (подробнее в секции «Симуляция»)
6. **Тестирование на реальном роботе**: запуск через `lerobot-record` с реальным роботом
7. **Деплой**: загрузка модели в MinIO, OTA-обновление на целевых роботах
8. **Мониторинг**: отслеживание success rate в production

### Процедура добавления нового типа робота (X-VLA)

1. **Назначение Domain ID**: выбрать свободный Domain ID (0–29) для конфигурации «робот + камеры»
2. **Выбор Action Mode**: рекомендуется `auto` — автоопределение размерности действий из датасета
3. **Создание Environment Processor**: написать env-specific процессор для нормализации суставов и координат нового робота
4. **Сбор демонстраций**: ~50 эпизодов для целевых задач
5. **Обучение Soft Prompts**: Phase II адаптация, ~3 000 шагов, ~1 час на A100. Обучаются только Soft Prompts (9M параметров) + Action Head
6. **Оценка**: тестирование в симуляции и на реальном оборудовании
7. **Деплой**: обновление единой X-VLA модели с новым Soft Prompt. Все предыдущие роботы продолжают работать без изменений

### Мультизадачное обучение

SmolVLA поддерживает обучение на нескольких задачах одновременно:

- Общая base model + отдельные LoRA-адаптеры для каждой задачи
- Альтернатива: единый адаптер, обученный на смеси задач (multi-task LoRA)
- Выбор адаптера определяется текстовой инструкцией: модель сама понимает, какую задачу выполнять

## Симуляция и оценка

### IsaacLab Arena

Для оценки обученных моделей без реального оборудования используется **IsaacLab Arena** — GPU-ускоренная симуляционная среда на базе NVIDIA Isaac Sim:

- **Поддерживаемые роботы**: GR1, G1, Galileo (гуманоиды), а также произвольные URDF-модели
- **Задачи**: манипуляция, навигация, координация в группе
- **Параллелизм**: сотни симуляций одновременно на одном GPU
- **Интеграция с LeRobot**: среды загружаются через EnvHub (HuggingFace Hub), SmolVLA eval checkpoint доступен
- **Физика**: полноценная физическая симуляция (контакты, трение, гравитация)

### EnvHub — реестр симуляционных сред

LeRobot EnvHub позволяет загружать готовые среды из HuggingFace Hub:

- Каждая среда имеет уникальный идентификатор на HuggingFace
- Поддерживается интерфейс `gym.vector.VectorEnv` для параллельного запуска
- Среды включают: описание задачи, reward function, начальные условия, критерии успеха
- Для AgentsSwarm можно создавать и публиковать собственные среды, моделирующие реальные условия работы роя

### Оценка через lerobot-record

CLI-утилита `lerobot-record` используется для оценки обученных моделей:

- **В симуляции**: подключение к IsaacLab Arena, автоматический прогон N эпизодов, подсчёт success rate
- **На реальном роботе**: управление роботом обученной политикой, запись результатов, оценка оператором
- Результаты сохраняются в формате LeRobot Dataset — могут быть использованы для дальнейшего дообучения (DAgger-подобный цикл)

### Метрики оценки

| Метрика | Описание | Целевое значение |
|---------|----------|-----------------|
| Success Rate (sim) | Доля успешных выполнений в симуляции | > 85% |
| Success Rate (real) | Доля успешных выполнений на реальном роботе | > 75% |
| Action MSE | Среднеквадратичная ошибка действий vs демонстрации | < 0.01 |
| Completion Time | Среднее время выполнения задачи | Зависит от задачи |
| X-VLA LIBERO | Benchmark для кросс-платформенных задач | > 93% (X-VLA reference) |

## Edge-Cloud синергия в обучении

### Облачное обучение, Edge-исполнение

1. Все демонстрации собираются и хранятся в облаке (MinIO)
2. Обучение выполняется на GPU-кластере в облаке
3. Готовые адаптеры конвертируются для edge (pruning + quantization)
4. Edge-адаптеры доставляются на роботов через OTA

### Continual Learning (непрерывное обучение)

Платформа поддерживает непрерывное улучшение моделей:

- Робот выполняет задачи в production
- Результаты (успех/неудача) логируются
- Неудачные кейсы анализируются
- Оператор предоставляет корректные демонстрации для проблемных случаев
- Модель дообучивается на расширенном датасете
- Обновлённые адаптеры деплоятся через OTA

### Защита от catastrophic forgetting

При дообучении на новых данных модель может «забыть» старые навыки. Защита:

- **Replay Buffer**: при каждом дообучении в батч добавляются примеры из старых задач
- **EWC (Elastic Weight Consolidation)**: регуляризация, защищающая важные параметры
- **Многозадачный LoRA**: отдельные адаптеры для разных задач, base model не меняется

## OTA-обновление моделей

### Механизм

1. Новая версия адаптера загружается в MinIO (бакет: model-updates)
2. Orchestrator отправляет MQTT-сообщение на топик robot/{robot_id}/model/update
3. Edge AI Proxy на роботе получает уведомление
4. Скачивает новый адаптер из MinIO
5. Выполняет конвертацию в TensorRT (если нужно)
6. Загружает новый адаптер (hot-swap, без остановки робота)
7. Подтверждает успешное обновление через MQTT

### Стратегии обновления

| Стратегия | Описание | Когда использовать |
|-----------|----------|-------------------|
| Immediate | Обновление сразу при получении | Критические исправления |
| Scheduled | Обновление в заданное время (ночью) | Плановые улучшения |
| Canary | Обновление 10% роботов, затем остальных | Новые адаптеры |
| Manual | По команде оператора | Экспериментальные модели |

### Откат

При обнаружении деградации после обновления:

- Автоматический откат: если success rate < порог в течение 30 минут
- Ручной откат: по команде оператора через Dashboard
- Предыдущая версия адаптера хранится локально на роботе для мгновенного отката
