# GatewayService — Обзор

## Назначение

GatewayService (API-шлюз) — единая точка входа для всех внешних запросов к системе. Все обращения от фронтенда, мобильных клиентов и внешних интеграций проходят через этот сервис.

---

## Зона ответственности

- Приём HTTP REST-запросов от клиентов
- Управление WebSocket-соединениями для real-time обновлений
- Аутентификация (проверка JWT-токенов) и авторизация (проверка ролей)
- Проксирование запросов к внутренним микросервисам
- Трансформация данных между внешним и внутренним форматами
- Rate limiting и защита от злоупотреблений
- Агрегация ответов от нескольких внутренних сервисов

## Архитектура внутри сервиса

### Слои

1. **Transport Layer** — обработка HTTP и WebSocket запросов, сериализация/десериализация
2. **Authentication Layer** — middleware для проверки JWT и извлечения контекста пользователя
3. **Authorization Layer** — проверка прав доступа для каждого эндпоинта
4. **Business Logic Layer** — маршрутизация запросов к нужным внутренним сервисам
5. **Integration Layer** — клиенты для RabbitMQ, Redis, gRPC

### WebSocket Manager

Компонент, отвечающий за управление долгоживущими WebSocket-соединениями:

- **Регистрация соединений** — при подключении клиента соединение регистрируется с привязкой к `user_id`
- **Маршрутизация сообщений** — входящие сообщения направляются в соответствующие обработчики (chat, subscription)
- **Fan-out обновлений** — при получении события из Redis Pub/Sub — пересылка всем подписанным клиентам
- **Heartbeat** — периодическая проверка активности соединения (ping/pong каждые 30 секунд)
- **Graceful disconnect** — корректное закрытие при отключении клиента или таймауте

## Масштабирование

- **Stateless-архитектура** — все состояние хранится в Redis (сессии, кэш), что позволяет запускать множество реплик
- **HPA** — автомасштабирование по CPU и количеству соединений
- **Session Affinity** — для WebSocket используется sticky sessions (через Ingress), чтобы клиент всегда попадал на тот же pod
- **Redis Pub/Sub** — при горизонтальном масштабировании Gateway pod'ы подписываются на Redis Pub/Sub для получения обновлений, независимо от того, на каком pod'е был инициирован запрос

---

## Обработка ошибок

- **Таймауты** — все исходящие запросы имеют настраиваемые таймауты (по умолчанию 10 секунд)
- **Circuit Breaker** — при недоступности внутреннего сервиса запросы к нему временно прекращаются
- **Retry** — автоматические повторы для идемпотентных запросов (GET) с экспоненциальным backoff
- **Structured Errors** — все ошибки возвращаются в едином формате с полями: `error_code`, `message`, `details`, `trace_id`
