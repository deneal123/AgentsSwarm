# GatewayService — REST API

## Общая информация

- **Базовый URL:** `/api/v1/`
- **Формат данных:** JSON
- **Аутентификация:** Bearer JWT в заголовке `Authorization`
- **Версионирование:** через путь (`/api/v1/`, `/api/v2/`)
- **Документация:** автогенерация через OpenAPI (Swagger UI доступен по `/docs`)

---

## Группы эндпоинтов

### Роботы

**Получение списка роботов**
- Метод: GET
- Путь: `/api/v1/robots`
- Параметры запроса: `status` (фильтр по статусу), `type` (фильтр по типу), `limit`, `offset`
- Ответ: массив объектов робота с полями `id`, `name`, `type`, `status`, `capabilities`, `last_seen_at`, `live_status` (из Redis)
- Роли: viewer, operator, admin

**Получение деталей робота**
- Метод: GET
- Путь: `/api/v1/robots/{robot_id}`
- Ответ: полная информация о роботе, включая текущую позицию, заряд, активную задачу
- Роли: viewer, operator, admin

**Историческая телеметрия робота**
- Метод: GET
- Путь: `/api/v1/robots/{robot_id}/telemetry`
- Параметры запроса: `from` (ISO 8601), `to` (ISO 8601), `sensor_type`, `resolution` (raw, 1m, 1h)
- Ответ: массив точек телеметрии из InfluxDB
- Роли: viewer, operator, admin

**Экстренная остановка робота**
- Метод: POST
- Путь: `/api/v1/robots/{robot_id}/emergency_stop`
- Описание: Приоритетная команда экстренной остановки. Отправляется через gRPC напрямую в Orchestrator → MQTT с QoS 2
- Таймаут: 2 секунды
- Ответ: статус отправки и `message_id`
- Роли: operator, admin

### Задачи

**Создание задачи**
- Метод: POST
- Путь: `/api/v1/tasks`
- Тело запроса: `robot_id` (опционально), `type`, `parameters`, `priority`
- Описание: альтернативный способ создания задачи (вместо чата). Публикуется в RabbitMQ
- Ответ: `task_id`, `status: "created"`
- Роли: operator, admin

**Получение статуса задачи**
- Метод: GET
- Путь: `/api/v1/tasks/{task_id}`
- Ответ: объект задачи с полями `id`, `robot_id`, `type`, `status`, `progress`, `created_at`, `started_at`, `completed_at`, `result`
- Роли: viewer, operator, admin

**Список задач**
- Метод: GET
- Путь: `/api/v1/tasks`
- Параметры запроса: `status`, `robot_id`, `limit`, `offset`, `sort_by`
- Ответ: массив задач с пагинацией
- Роли: viewer, operator, admin

### Рой (Swarm)

**Статус роя**
- Метод: GET
- Путь: `/api/v1/swarm/status`
- Ответ: агрегированная информация: количество роботов по статусам, активные задачи, последний анализ AI, предупреждения
- Роли: viewer, operator, admin

**Визуальный анализ робота**
- Метод: POST
- Путь: `/api/v1/vision/analyze_robot`
- Параметры запроса: `robot_id`
- Описание: запрашивает анализ последнего изображения робота через Triton + vLLM
- Ответ: список детекций, текстовый анализ сцены, рекомендации
- Роли: operator, admin

### Чат (альтернативный REST-эндпоинт)

**Отправка сообщения**
- Метод: POST
- Путь: `/api/v1/chat/message`
- Тело запроса: `message` (строка), `user_id` (опционально)
- Описание: синхронный эндпоинт для отправки команды на естественном языке. Возвращает результат после полной обработки (может занять несколько секунд)
- Ответ: `user_message`, `responses` (массив шагов обработки), `final_plan`
- Роли: operator, admin

### Администрирование

**Список пользователей**
- Метод: GET
- Путь: `/api/v1/admin/users`
- Роли: admin

**Обновление конфигурации**
- Метод: PUT
- Путь: `/api/v1/admin/config`
- Описание: обновление глобальных параметров системы
- Роли: admin

**Управление моделями**
- Метод: POST
- Путь: `/api/v1/admin/models/deploy`
- Описание: инициирует обновление AI-модели на роботах
- Роли: admin

## Формат ответов

### Успешный ответ

Каждый успешный ответ содержит:
- HTTP-код 200 (для GET), 201 (для POST с созданием), 204 (для DELETE)
- Тело: JSON с данными

### Ответ с ошибкой

Каждый ответ с ошибкой содержит:
- Соответствующий HTTP-код (400, 401, 403, 404, 500, 503)
- Тело: JSON с полями `error_code` (строка, машиночитаемый код), `message` (строка, человекочитаемое описание), `details` (объект, дополнительная информация), `trace_id` (строка, идентификатор для отладки)

### Пагинация

Все списочные эндпоинты поддерживают пагинацию:
- Параметры запроса: `limit` (по умолчанию 50, максимум 200), `offset`
- Ответ содержит: `total` (общее количество), `limit`, `offset`, `items` (массив данных)

## Rate Limiting

| Эндпоинт | Лимит | Окно |
|----------|-------|------|
| GET-запросы | 200 запросов | 1 минута |
| POST-запросы | 50 запросов | 1 минута |
| Emergency stop | 10 запросов | 1 минута |
| Chat message | 20 запросов | 1 минута |

При превышении лимита возвращается HTTP 429 (Too Many Requests) с заголовком `Retry-After`.
