# Orchestrator — Координация роя

## Назначение

CoordinationManager отвечает за согласование действий нескольких роботов при выполнении совместных задач, предотвращение конфликтов и реализацию алгоритмов роевого интеллекта.

---

## Задачи координации

### Распределение зон ответственности

При задаче поиска объектов в большой области CoordinationManager разделяет пространство на зоны и назначает каждому роботу свою зону. Критерии разделения:
- Площадь зон пропорциональна возможностям робота (быстрый робот получает большую зону)
- Минимизация пересечений маршрутов
- Начальная позиция робота учитывается для минимизации времени перемещения

Распределение зон реализуется через Coordination Agent, который вызывается из узла Generate Plan (LangGraph) в паттерне agents-as-tools. Координационный агент использует инструмент balance_workload для оптимизации назначений, а результат возвращается как часть плана в SwarmState.

### Избегание столкновений

Система координирует маршруты роботов для предотвращения столкновений:
- Каждый робот публикует свой запланированный маршрут в Redis
- CoordinationManager проверяет пересечения маршрутов
- При обнаружении конфликта — один из роботов получает команду ожидания или изменения маршрута
- Приоритет определяется: приоритетом задачи → зарядом батареи → идентификатором робота

Проверка столкновений выполняется через инструмент assess_collision_risk агента Safety Agent, который вызывается как перед выполнением плана (через guardrail паттерна evaluator-optimizer), так и периодически в узле Monitor Execution.

### Совместные манипуляции

Некоторые задачи требуют координированного действия нескольких роботов:
- Перемещение крупного объекта двумя роботами
- Синхронная инспекция объекта с разных сторон
- Формирование (построение группы роботов в определённую конфигурацию)

Для таких задач CoordinationManager:
1. Определяет роли каждого робота (ведущий/ведомый)
2. Синхронизирует старт действия через MQTT (все роботы начинают одновременно)
3. Контролирует синхронность выполнения через телеметрию

Координация совместных манипуляций реализуется через инструмент coordinate_formation агента Coordination Agent. Параметр formation_type валидируется через Pydantic Field с ограничением на допустимые значения (line, ring, wedge, free). Инструмент send_command определён с условным включением (is_enabled) — доступен только в рабочем режиме и автоматически отключается в режиме симуляции.

## Мультиагентная координация

### Взаимодействие агентов при координации

Агенты Open-Agent SDK обеспечивают координацию роя через два паттерна:

**Паттерн Manager (agents-as-tools):**
- Узлы LangGraph (Execute Plan, Monitor Execution) вызывают Coordination Agent как инструмент
- Coordination Agent использует свой набор инструментов (assign_robot, coordinate_formation, resolve_conflict, balance_workload, send_command)
- Результаты возвращаются в SwarmState для дальнейшей обработки в графе

**Паттерн Handoffs (делегация):**
- Coordination Agent может делегировать задачу Vision Agent для уточнения позиций объектов перед координацией формации
- При обнаружении конфликта маршрутов Coordination Agent делегирует Safety Agent для оценки рисков столкновения
- Делегация происходит через handoff-механизм Open-Agent SDK: управление полностью передаётся целевому агенту, который возвращает результат по завершении

### Human-in-the-loop для критических координационных действий

Инструмент emergency_stop агента Safety Agent определён с needs_approval — при вызове выполнение приостанавливается и создаётся interruption. Оператор через Dashboard UI подтверждает или отклоняет экстренную остановку. Состояние сериализуется через to_state() и возобновляется после решения оператора.

## Алгоритмы роевого интеллекта

### Particle Swarm Optimization (PSO)

Используется для оптимального распределения задач между роботами:
- Каждый робот — «частица» в пространстве решений
- Оптимизируемая функция: общее время выполнения всех задач
- Учитывает позиции, скорости, возможности роботов

### Dynamic Task Allocation

Динамическое перераспределение задач при изменении условий:
- Робот завершил задачу → ищется следующая ближайшая незанятая задача
- Робот разрядился → его задача передаётся ближайшему свободному роботу
- Обнаружена новая цель → ближайший свободный робот назначается на неё

### Consensus-Based Bundle Algorithm (CBBA)

Для сложных сценариев с множеством задач и роботов:
- Каждый робот оценивает стоимость выполнения каждой задачи
- Роботы обмениваются оценками через Orchestrator
- Итеративный процесс до достижения консенсуса о назначениях
- Гарантирует оптимальное распределение при минимальной коммуникации

## Карта среды

### Глобальная карта

CoordinationManager поддерживает глобальную карту, агрегируя данные от всех роботов:

- **Хранение:** Redis (актуальная версия) + Neo4j (графовая структура объектов и связей)
- **Обновление:** при каждом обновлении локальной карты от робота
- **Содержание:** занятые/свободные зоны, обнаруженные объекты с координатами, позиции всех роботов, зоны неопределённости

### Интеграция локальных карт

Каждый робот строит свою локальную карту (через LocalMapper на ROS2). При каждом обновлении:
1. Робот отправляет дельту карты через MQTT
2. Data Aggregation Service обновляет глобальную карту в Redis
3. CoordinationManager использует глобальную карту для планирования

## Управление конфликтами

### Типы конфликтов

| Тип | Описание | Решение |
|-----|----------|---------|
| Маршрутный конфликт | Два робота движутся по пересекающимся маршрутам | Один робот ждёт, другой проезжает первым |
| Ресурсный конфликт | Два робота назначены на одну задачу | Отменяется назначение менее подходящего робота |
| Целевой конфликт | Два робота движутся к одному объекту | Ближайший робот продолжает, дальний перенаправляется |
| Зарядный конфликт | Несколько роботов нуждаются в зарядке одновременно | Очерёдность по критичности заряда |

### Протокол разрешения

1. Конфликт обнаруживается через анализ Redis-данных (позиции, маршруты, назначения)
2. CoordinationManager определяет тип конфликта
3. Применяется соответствующая стратегия разрешения
4. Обновлённые команды отправляются задействованным роботам
5. Событие логируется для анализа

## Формации и групповое поведение

### Типы формаций

- **Линия** — роботы выстраиваются в линию (для прочёсывания территории)
- **Кольцо** — роботы окружают объект (для инспекции)
- **Клин** — роботы движутся клином (для транспортировки)
- **Свободная** — роботы распределяются оптимально по площади

### Поддержание формации

- Каждый робот знает свою позицию в формации (offset относительно лидера или центра)
- Позиции обновляются в реальном времени через MQTT
- При отклонении от формации — корректирующие команды
- При выходе робота из формации (разряд, ошибка) — формация перестраивается
