# Robot Edge — Edge AI Proxy

## Назначение

Edge AI Proxy — центральный компонент AI-подсистемы на борту робота. Управляет локальными AI-моделями, принимает решения о маршрутизации inference-запросов (локально или в облако), обеспечивает отказоустойчивость при потере связи.

---

## Архитектура

### Компоненты

1. **Model Manager**: загрузка, выгрузка и переключение AI-моделей в GPU-памяти
2. **Inference Router**: принятие решения о маршруте запроса (edge/cloud/hybrid)
3. **Request Queue**: очередь запросов с приоритизацией
4. **OTA Updater**: управление обновлениями моделей
5. **Health Monitor**: мониторинг состояния моделей и GPU

---

## Model Manager

### Управление жизненным циклом моделей

Model Manager отвечает за все операции с моделями на edge:

- **Загрузка**: инициализация модели в GPU-памяти при старте или по требованию
- **Выгрузка**: освобождение GPU-памяти при нехватке ресурсов
- **Переключение версий**: hot-swap адаптеров SmolVLA без остановки inference
- **Мониторинг**: отслеживание использования памяти, латентности, ошибок

### Реестр моделей

Model Manager поддерживает локальный реестр моделей:

| Поле | Описание |
|------|----------|
| model_id | Уникальный идентификатор модели |
| model_type | Тип (smolvla, yolo, depth, segmentation) |
| version | Версия модели |
| format | Формат (onnx, tensorrt, pytorch) |
| status | Статус (loaded, unloaded, loading, error) |
| memory_usage | Использование GPU-памяти |
| last_inference | Время последнего inference |
| error_count | Количество ошибок |

### Стратегия загрузки

При старте загружаются обязательные модели:

1. **Tiny YOLO** — всегда загружена (навигация, безопасность)
2. **SmolVLA Edge** — загружается при наличии задач манипуляции
3. **MiDaS Small** — загружается по требованию (оценка глубины)

При нехватке GPU-памяти: модели с наименьшим приоритетом и наибольшим временем простоя выгружаются первыми (LRU + приоритет).

## Inference Router

### Логика маршрутизации

Inference Router определяет, где выполнить inference — на edge или в облаке:

| Фактор | Edge | Cloud | Обоснование |
|--------|------|-------|-------------|
| Связь с облаком | Нет | Да | Offline — только edge |
| Латентность критична | Да | Нет | Реактивное управление — edge |
| Сложная задача | Нет | Да | Cloud-модели мощнее |
| GPU-нагрузка high | Нет | Да | Разгрузка edge |
| Батарея low | Да (минимум) | Да | Экономия энергии |

### Алгоритм принятия решения

1. Проверить доступность связи с облаком
2. Если нет связи → edge
3. Если запрос критичный по латентности (< 100 мс) → edge
4. Если локальная модель не загружена / занята → cloud
5. Если задача сложная (multi-step manipulation) → cloud (SmolVLA 450M)
6. Иначе → edge (SmolVLA 150M)

### Гибридный режим

В гибридном режиме Router одновременно:

- Отправляет запрос на edge (быстрый, менее точный результат)
- Отправляет запрос в cloud (медленнее, но точнее)
- Использует edge-результат немедленно
- Когда приходит cloud-результат — корректирует действия, если расхождение значительное

## Request Queue

### Приоритизация

| Приоритет | Тип запроса | Max Wait | Описание |
|-----------|------------|----------|----------|
| 0 (критический) | Safety inference | 50 мс | Обнаружение опасности |
| 1 (высокий) | Manipulation action | 100 мс | Текущее действие манипулятора |
| 2 (средний) | Navigation detection | 200 мс | Детекция для навигации |
| 3 (низкий) | Scene analysis | 1 сек | Фоновый анализ сцены |

### Вытеснение

При переполнении очереди (GPU не успевает обрабатывать):

- Низкоприоритетные запросы отбрасываются
- Критические запросы никогда не отбрасываются
- Отброшенные запросы перенаправляются в cloud (если есть связь)

## OTA Updater

### Механизм обновления

1. **Уведомление**: MQTT-сообщение от Orchestrator на топик robot/{robot_id}/model/update
2. **Загрузка**: скачивание новой модели/адаптера из MinIO по HTTPS
3. **Верификация**: проверка контрольной суммы (SHA-256) и цифровой подписи
4. **Конвертация**: при необходимости — конвертация ONNX → TensorRT (выполняется в фоне)
5. **Тестирование**: запуск тестового inference на эталонном входе, проверка корректности выхода
6. **Активация**: загрузка новой модели, выгрузка старой
7. **Подтверждение**: MQTT-сообщение с результатом обновления

### Безопасность обновлений

- Каждая модель подписана цифровой подписью
- Подпись проверяется перед загрузкой в GPU
- При ошибке верификации — обновление отклоняется, отправляется алерт
- Предыдущая версия всегда сохраняется локально для отката

### Управление дисковым пространством

На edge ограничено дисковое пространство (SSD на Jetson):

- Хранятся максимум 2 версии каждой модели (текущая + предыдущая)
- При нехватке места — удаляется самая старая неиспользуемая версия
- Модели в формате TensorRT кэшируются (не пересоздаются при каждом обновлении, если GPU-архитектура не изменилась)

## Health Monitor

### Контролируемые параметры

| Параметр | Порог Warning | Порог Critical | Действие |
|----------|--------------|----------------|----------|
| GPU Temperature | > 80°C | > 90°C | Снижение тактовой частоты / остановка inference |
| GPU Memory | > 85% | > 95% | Выгрузка низкоприоритетных моделей |
| Inference Latency | > 2× нормы | > 5× нормы | Алерт, переключение на cloud |
| Error Rate | > 5% | > 20% | Перезагрузка модели, откат версии |
| Disk Space | < 2 GB | < 500 MB | Очистка кэша, алерт |

### Самовосстановление

При обнаружении проблем Health Monitor выполняет автоматические действия:

- **Перезагрузка модели**: если модель начала возвращать ошибки
- **Откат версии**: если новая версия работает хуже старой
- **Переключение на CPU**: если GPU недоступен (перегрев, ошибка)
- **Переключение на cloud**: если локальные модели не работают
- **Перезагрузка контейнера**: если процесс завис
