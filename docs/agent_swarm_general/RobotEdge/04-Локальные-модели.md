# Локальные модели на Edge

## Назначение

Набор лёгких моделей, запускаемых непосредственно на роботе для обеспечения автономности и быстрого реагирования. Модели работают внутри контейнеров edge-ai-proxy, smolvla-edge и tiny-yolo, управляются через Model Manager (см. 02-Edge-AI-Proxy).

---

## Типы локальных моделей

| Модель | Задача | Размер (FP16) | Размер (INT8) | Латентность (Jetson Orin NX) |
|--------|--------|-------------|-------------|------------------------------|
| Tiny YOLO v8n | Быстрая детекция объектов | ~12 MB | ~6 MB | ~8 мс |
| NanoDet-Plus | Альтернативный детектор (легче) | ~4 MB | ~2 MB | ~5 мс |
| SmolVLA Edge (~150M) | Визуально-языковая модель для принятия решений | ~400 MB (INT8) | ~200 MB (INT4) | ~80 мс |
| MiDaS Small | Облегчённая оценка глубины | ~80 MB | ~40 MB | ~15 мс |
| MoveNet Lightning | Оценка позы человека (17 ключевых точек) | ~10 MB | ~5 MB | ~6 мс |
| Obstacle Classifier | Классификатор проходимости (бинарный) | ~5 MB | ~3 MB | ~3 мс |

## Выбор форматов и runtime

### Форматы моделей

| Формат | Применение | Обоснование |
|--------|-----------|-------------|
| TensorRT | NVIDIA Jetson (основной) | Максимальная производительность на Jetson GPU |
| ONNX | Универсальный / fallback | Переносимость, конвертация в TensorRT на устройстве |
| TFLite | ARM с NPU (без Jetson) | Для устройств без CUDA |
| TVM compiled | Специализированные ускорители | Оптимизация под конкретную архитектуру |

### Runtime-среда

Все модели исполняются в Python-среде ROS 2 Jazzy контейнера, имеющей доступ к:

- **python3-opencv** — предварительная обработка изображений (resize, нормализация, цветовые пространства)
- **python3-numpy** — операции с тензорами, пост-процессинг (NMS, фильтрация)
- **TensorRT Python API** — запуск TensorRT-движков
- **ONNX Runtime** — fallback при отсутствии TensorRT-плана

### Конвертация ONNX → TensorRT на устройстве

При OTA-обновлении модели могут поставляться в формате ONNX. Конвертация в TensorRT выполняется локально на Jetson:

1. Edge AI Proxy получает ONNX-модель из MinIO
2. Проверяет цифровую подпись и контрольную сумму
3. Запускает trtexec для конвертации с параметрами целевого устройства (FP16/INT8, dynamic shapes)
4. Кэширует TensorRT-план (повторная конвертация не нужна, если GPU-архитектура не изменилась)
5. Загружает сконвертированную модель в GPU-память

Конвертация выполняется в фоновом режиме; текущая версия модели продолжает работать до завершения.

## Интеграция моделей с ROS 2

### Модели как ROS 2 узлы

Каждая модель оформляется как ROS 2 узел (ament_python пакет), что обеспечивает:

- Стандартный интерфейс подписки на сенсорные топики
- Публикацию результатов в ROS 2 топики (детекции, маски, команды)
- Управление через ROS 2 параметры (порог уверенности, частота inference)
- Мониторинг через стандартные средства ROS 2 (ros2 node info, rqt)

### Примеры потоков данных

**Детекция для навигации:**
/camera/image_raw → tiny_yolo_node → /detections → navigation_stack

**Оценка глубины:**
/camera/image_raw → midas_node → /depth_estimate → obstacle_avoidance

**SmolVLA для манипуляции:**
/camera/image_raw + /task_description → smolvla_node → /manipulation_action → task_executor

### Сборка inference-пакетов

Inference-узлы собираются через colcon как обычные ROS 2 пакеты:

- Модельные веса хранятся отдельно (в /models/ или MinIO), не в пакете
- Пакет содержит только логику: загрузка модели, pre/post-processing, публикация результатов
- При сборке с --symlink-install изменения в логике видны сразу без пересборки

## Жизненный цикл модели

### Загрузка

1. При старте контейнера Model Manager проверяет наличие моделей в локальном хранилище
2. Обязательные модели (Tiny YOLO) загружаются в GPU-память
3. Опциональные модели (SmolVLA, MiDaS) загружаются по требованию или при наличии соответствующих задач

### Проверка целостности

- Каждая модель имеет файл манифеста (SHA-256, версия, подпись)
- При загрузке вычисляется контрольная сумма и сверяется с манифестом
- При несовпадении — модель не загружается, отправляется алерт, используется предыдущая версия

### OTA-обновление

- Orchestrator отправляет MQTT-уведомление о доступности новой версии
- Edge AI Proxy скачивает модель из MinIO по HTTPS
- Проводится верификация → конвертация (ONNX → TensorRT) → тестовый inference → активация
- Предыдущая версия сохраняется для отката

### Откат

При обнаружении деградации качества или ошибок после обновления:

- Health Monitor фиксирует рост error_rate или деградацию латентности
- Автоматический откат к предыдущей версии
- Уведомление Orchestrator об откате через MQTT
- На устройстве хранятся максимум 2 версии каждой модели (текущая + предыдущая)

## Квантизация и оптимизация

### INT8 калибрация

Для максимальной производительности на Jetson модели квантизуются до INT8:

- Калибровочный датасет (100–500 изображений) готовится в облаке
- Калибровочные таблицы поставляются вместе с ONNX-моделью
- trtexec использует таблицы для создания INT8 TensorRT-плана
- Потеря точности контролируется: mAP drop < 1% для YOLO, < 2% для MiDaS

### Layer Fusion и оптимизации TensorRT

TensorRT автоматически применяет:

- Слияние слоёв (Conv + BN + ReLU → один kernel)
- Оптимизацию memory layout (NHWC vs NCHW в зависимости от GPU)
- Kernel auto-tuning под конкретную GPU-архитектуру Jetson

## Ограничения

- Ограниченный объём GPU-памяти (8–64 GB в зависимости от модели Jetson)
- Необходимость агрессивной оптимизации и тестирования на целевом железе
- TensorRT-планы не переносимы между разными GPU-архитектурами (нужна переконвертация)
- При одновременной работе нескольких моделей — конкуренция за GPU-ресурсы (управляется через Model Manager)
- SmolVLA Edge (150M) имеет ограниченные reasoning-способности по сравнению с cloud-версией (450M)
