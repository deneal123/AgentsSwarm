# Robot Edge — Обзор

## Назначение

Robot Edge — программный стек, работающий непосредственно на бортовом компьютере каждого робота. Обеспечивает локальную обработку данных, автономное управление, взаимодействие с сенсорами и актуаторами, связь с облаком.

---

## Зона ответственности

- Локальный AI-inference на edge-устройстве (Jetson)
- Трансляция между ROS2-топиками робота и облачными сервисами
- Управление локальными моделями (загрузка, обновление, переключение)
- Автономная работа при потере связи с облаком
- Сбор и локальная буферизация телеметрии
- Обеспечение безопасности на уровне робота (watchdog, ограничения)

---

## Аппаратная платформа

### NVIDIA Jetson

| Платформа | GPU | CPU | RAM | Применение |
|-----------|-----|-----|-----|------------|
| Jetson AGX Orin 64GB | 2048 CUDA cores, 275 TOPS | 12-core Arm Cortex-A78AE | 64 GB LPDDR5 | Флагманские роботы, полный набор моделей |
| Jetson Orin NX 16GB | 1024 CUDA cores, 100 TOPS | 8-core Arm Cortex-A78AE | 16 GB LPDDR5 | Основная платформа, SmolVLA + Tiny YOLO |
| Jetson Orin Nano 8GB | 512 CUDA cores, 40 TOPS | 6-core Arm Cortex-A78AE | 8 GB LPDDR5 | Бюджетные роботы, только Tiny YOLO |

### Периферия

- Камеры: USB/CSI камеры (RGB, опционально Depth)
- LiDAR: 2D/3D LiDAR через USB или Ethernet
- IMU: инерциальный блок измерений
- Моторы/сервоприводы: через CAN-bus или серийный интерфейс
- Сеть: Wi-Fi 6, Ethernet, опционально 4G/5G модем

## Архитектура программного стека

### Уровни

1. **JetPack OS**: операционная система NVIDIA для Jetson (Linux4Tegra)
2. **Docker Runtime**: все компоненты работают в Docker-контейнерах
3. **ROS 2 Jazzy**: робототехнический middleware (LTS, май 2024). Базовый образ: `osrf/ros:jazzy-desktop-full`
4. **Edge AI Proxy**: управление AI-моделями и маршрутизацией
5. **ROS2 Bridge + Foxglove Bridge**: трансляция между ROS2 и облачными протоколами, WebSocket-визуализация данных (порт 8765)
6. **Application Layer**: бизнес-логика, task executor, safety monitor

### Контейнеризация

Все компоненты edge-стека работают в Docker-контейнерах на Jetson:

| Контейнер | Описание | GPU | Restart Policy |
|-----------|----------|-----|----------------|
| edge-ai-proxy | Управление AI-моделями | Да | always |
| ros2-bridge | Трансляция ROS2 ↔ MQTT | Нет | always |
| foxglove-bridge | WebSocket-мост для визуализации ROS 2 данных (порт 8765) | Нет | always |
| smolvla-edge | SmolVLA inference | Да | always |
| tiny-yolo | Локальная детекция | Да | always |
| telemetry-agent | Сбор и отправка телеметрии | Нет | always |
| safety-watchdog | Мониторинг безопасности | Нет | always |
| task-executor | Выполнение задач | Нет | always |
| vnc-debug | noVNC-сервер для удалённой отладки (порт 6080), включается по флагу | Нет | unless-stopped |

### Оркестрация контейнеров

На edge используется Docker Compose (не Kubernetes — слишком тяжёл для Jetson). Docker Compose файл определяет все контейнеры, зависимости, ресурсные ограничения и порядок запуска. При обновлении — пересоздание отдельных контейнеров без остановки остальных.

### Базовый Docker-образ

Контейнеры ros2-bridge и foxglove-bridge строятся на основе образа `osrf/ros:jazzy-desktop-full` (для разработки) или облегчённого `osrf/ros:jazzy-ros-base` (для production). Образ включает:

- ROS 2 Jazzy с полным набором инструментов (colcon, rosdep, rviz2, rqt)
- Python 3 с научными библиотеками (numpy, matplotlib, opencv)
- Foxglove Bridge для WebSocket-визуализации
- Систему сборки colcon с поддержкой ament_python и ament_cmake

Для production-развёртывания образ оптимизируется: убираются GUI-компоненты (VNC, XFCE), шрифты и учебные пакеты; добавляются MQTT-клиент (paho-mqtt), gRPC-библиотеки (grpcio + protobuf) и Edge AI зависимости.

### Удалённая отладка через noVNC

Для полевой диагностики на роботе может быть активирован контейнер vnc-debug, предоставляющий:

- Полный графический рабочий стол XFCE через браузер (http://robot_ip:6080/vnc.html)
- VNC-доступ через порт 5901 для прямого подключения VNC-клиентом
- Инструменты визуализации: RViz2, rqt_graph, rqt_console, rqt_plot
- Управление роботом через teleop_twist_keyboard
- Доступ к Foxglove Studio Web (через Foxglove Bridge на порту 8765)

Контейнер vnc-debug включается только при необходимости (флаг в Docker Compose) и защищён паролем. В production-среде рекомендуется дополнительно туннелировать через SSH/VPN и ограничивать время сессии.

## Взаимодействие

### С облаком

| Канал | Протокол | Направление | Описание |
|-------|----------|-------------|----------|
| Телеметрия | MQTT (QoS 1) | Edge → Cloud | Состояние робота, батарея, позиция |
| Команды | MQTT (QoS 2) | Cloud → Edge | Задачи, управляющие команды |
| Vision (fallback) | gRPC Streaming | Edge → Cloud | Изображения для cloud inference |
| Модели | HTTPS (MinIO S3) | Cloud → Edge | OTA-обновления моделей |
| Метрики | MQTT (QoS 0) | Edge → Cloud | Системные метрики для Prometheus |
| Визуализация | WebSocket (Foxglove Bridge, порт 8765) | Edge → Frontend | Данные ROS 2 топиков в реальном времени для 3D-визуализации |
| Отладка | HTTP/WebSocket (noVNC, порт 6080) | Оператор ↔ Edge | Удалённый GUI-доступ к ROS 2 стеку |

### Внутренняя (ROS2)

| Топик | Тип | Описание |
|-------|-----|----------|
| /camera/image_raw | sensor_msgs/Image | Изображение с камеры |
| /scan | sensor_msgs/LaserScan | Данные LiDAR |
| /imu/data | sensor_msgs/Imu | Данные IMU |
| /odom | nav_msgs/Odometry | Одометрия |
| /cmd_vel | geometry_msgs/Twist | Команда скорости (навигация) |
| /joint_states | sensor_msgs/JointState | Состояние суставов |
| /joint_trajectory | trajectory_msgs/JointTrajectory | Команда для манипулятора |
| /robot_status | custom_msgs/RobotStatus | Сводный статус робота |

## Жизненный цикл робота

### Загрузка

1. Jetson включается, загружает JetPack OS
2. Docker Compose запускает все контейнеры
3. Safety Watchdog стартует первым, инициализирует мониторинг
4. Edge AI Proxy загружает модели в GPU-память
5. ROS2 Bridge устанавливает MQTT-соединение с облаком
6. Task Executor сообщает облаку о готовности (статус: IDLE)

### Нормальная работа

- Получение задач от Orchestrator через MQTT
- Выполнение задач с использованием локальных моделей и ROS2
- Отправка телеметрии в облако каждые 1–5 секунд
- Периодическая проверка обновлений моделей

### Отключение

1. Orchestrator отправляет команду graceful shutdown
2. Task Executor завершает текущую задачу (или ставит на паузу)
3. Робот переходит в безопасную позицию
4. Отправляется финальный пакет телеметрии
5. Контейнеры останавливаются через Docker Compose down

## Управление ресурсами

### GPU

GPU-память Jetson разделяется между моделями:

| Модель | Память (FP16) | Память (INT8) | Приоритет |
|--------|-------------|-------------|-----------|
| SmolVLA Edge | 800 MB | 400 MB | Высокий |
| Tiny YOLO | 200 MB | 100 MB | Средний |
| Глубина (MiDaS small) | 300 MB | 150 MB | Низкий |
| Резерв | — | — | — |

При нехватке памяти низкоприоритетные модели выгружаются.

### CPU

- ROS2 ноды: 2–4 ядра
- Docker overhead: 1 ядро
- Системные процессы: 1–2 ядра
- Модели (CPU fallback): оставшиеся ядра

### Энергопотребление

Jetson поддерживает профили мощности (NVPModel):

| Профиль | Мощность | Применение |
|---------|---------|------------|
| MAXN | 15–60W | Максимальная производительность (активная работа) |
| 15W | 15W | Сбалансированный (навигация) |
| 10W | 10W | Энергосбережение (ожидание) |

Переключение профилей автоматическое, на основе текущей нагрузки и уровня заряда батареи.

## Среда разработки Edge-стека

### Рабочий процесс разработчика

Для разработки и тестирования Edge-компонентов без физического робота используется Docker-образ на базе `osrf/ros:jazzy-desktop-full` с VNC-доступом:

1. Сборка и запуск dev-контейнера с монтированием ros2_ws
2. Подключение через VS Code Remote Containers или noVNC в браузере (http://localhost:6080/vnc.html)
3. Создание ROS 2 пакетов (ament_python) в ~/ros2_ws/src/
4. Сборка через colcon build --symlink-install (алиас: cb)
5. Активация workspace через source install/setup.bash (алиас: cs)
6. Тестирование с помощью ros2 topic pub, ros2 topic echo, rqt_graph
7. Визуализация через Foxglove Studio Web (ws://localhost:8765)

### Структура ROS 2 Workspace

Все Edge ROS 2 пакеты организованы в единый workspace:

| Директория | Назначение |
|-----------|-----------|
| ros2_ws/src/ | Исходный код пакетов (версионируется в Git) |
| ros2_ws/build/ | Временные файлы сборки (создаётся colcon, не версионируется) |
| ros2_ws/install/ | Установленные пакеты (создаётся colcon, не версионируется) |
| ros2_ws/log/ | Логи сборки (не версионируется) |

### Инструменты отладки

| Инструмент | Назначение |
|-----------|-----------|
| RViz2 | 3D-визуализация робота, облака точек, карт, маркеров |
| rqt_graph | Граф узлов и топиков — структура системы |
| rqt_console | Просмотр логов всех узлов в реальном времени |
| rqt_plot | Построение графиков значений топиков |
| teleop_twist_keyboard | Ручное управление роботом с клавиатуры через /cmd_vel |
| tf2_tools | Визуализация дерева систем координат |
| Foxglove Studio Web | Браузерная альтернатива RViz с поддержкой графиков, 3D, логов |
| ros2 doctor | Диагностика проблем ROS 2 среды |
