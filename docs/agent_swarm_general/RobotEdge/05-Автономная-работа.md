# Автономная работа робота

## Цель

Описать режимы автономной работы робота при частичном или полном отсутствии связи с облаком, включая политики поведения, безопасность, диагностику и синхронизацию данных.

---

## Режимы автономности

### Полная автономия (Offline)

При полной потере связи с облаком (> 30 секунд без ответа MQTT-брокера) робот переходит в автономный режим:

- Локальный стек ROS 2 Jazzy продолжает работу без изменений
- Edge AI Proxy использует только локальные модели (Tiny YOLO, SmolVLA Edge, MiDaS)
- Навигация, избегание препятствий, базовые задачи — выполняются полностью локально
- Telemetry Agent буферизует данные в локальное хранилище (LMDB/SQLite)
- Новые задачи от Orchestrator не поступают; текущие задачи выполняются до завершения или ставятся на паузу
- Максимальная продолжительность автономной работы: 30+ минут (ограничена зарядом батареи и объёмом локального хранилища)

### Ограниченная автономия (Degraded)

При нестабильной связи (потеря > 50% пакетов, latency > 2 с):

- Критические задачи (safety, навигация) выполняются локально
- Сложные задачи (multi-step manipulation, cooperative tasks) откладываются до восстановления
- Bridge переключается на приоритетную отправку: только safety-события и ключевые метаданные
- Большие payload (изображения, облака точек) кэшируются локально

### Телеоперирование (Manual)

При наличии стабильной связи оператор может дистанционно управлять роботом:

- Через Gateway API → MQTT → Bridge → /cmd_vel
- Через teleop_twist_keyboard (при подключении через noVNC)
- Через Foxglove Studio Web (визуализация + управление, ws://robot_ip:8765)

## Политики поведения

### Приоритизация

Все решения робота в автономном режиме подчиняются приоритетам:

| Приоритет | Категория | Примеры |
|-----------|-----------|---------|
| 0 (критический) | Safety | Emergency stop, обход людей, реакция на столкновение |
| 1 (высокий) | Mission-critical | Завершение текущей задачи, возврат на базу |
| 2 (средний) | Operational | Навигация, патрулирование |
| 3 (низкий) | Non-critical | Фоновый анализ, отправка некритичной телеметрии |

### Политики заряда батареи

| Уровень заряда | Действие |
|---------------|----------|
| > 30% | Нормальная работа |
| 20–30% | Предупреждение Orchestrator, планирование возврата на зарядку |
| 10–20% | Прерывание некритичных задач, движение к ближайшей зарядной станции |
| < 10% | Аварийный режим: остановка всех задач, минимальное энергопотребление, emergency beacon |

Профиль мощности Jetson (NVPModel) автоматически переключается: 10W при ожидании → 15W при навигации → MAXN при активном AI-inference.

### Политики данных

В автономном режиме Bridge сокращает объём генерируемых данных:

- Камера: снижение частоты до 0.5 FPS, повышение компрессии (JPEG quality 40%)
- Телеметрия: агрегация за 10-секундные окна вместо поточной отправки
- Логи: только ERROR и WARNING уровни
- Детекции: отправляются только при обнаружении нового объекта или изменении сцены

## Синхронизация при восстановлении связи

### Процедура синхронизации

1. Bridge обнаруживает восстановление MQTT-соединения (LWT mechanism)
2. Отправляется текущий статус робота (retained message)
3. Буферизованная телеметрия отправляется в порядке приоритета:
   - Safety-события (incidenty, аварии) — немедленно
   - Результаты задач — следующие
   - Обычная телеметрия — в фоне
4. Orchestrator синхронизирует состояние задач (что было выполнено, что нужно переназначить)
5. Edge проверяет наличие OTA-обновлений моделей

### Конфликт-решение

При конфликте между локальными и облачными командами:

| Ситуация | Правило |
|----------|---------|
| Две команды на один робот | Приоритет: safety > manual > orchestrator |
| Conflicting navigate goals | Применяется команда с более высоким приоритетом |
| Локальная задача завершена, облако не знает | Edge отправляет task_completed, Orchestrator обновляет статус |
| Облако отменило задачу, Edge её выполнил | Orchestrator принимает результат, логирует расхождение |

## Диагностика и мониторинг в автономном режиме

### Локальный мониторинг

Даже без связи с облаком доступны инструменты диагностики:

- **Foxglove Bridge** (порт 8765): если оператор находится в локальной сети робота — подключение через Foxglove Studio Web для визуализации всех ROS 2 топиков
- **noVNC** (порт 6080, если контейнер vnc-debug включён): полный графический рабочий стол с RViz2, rqt_graph, rqt_console для глубокой диагностики
- **Локальные логи**: все ROS 2 узлы пишут структурированные логи в ~/ros2_ws/log/ и в Docker logs

### Удалённая диагностика при восстановлении связи

При восстановлении связи оператор может:

1. Открыть Dashboard UI → выбрать робот → кнопка «Remote Debug»
2. Gateway создаёт SSH-туннель к порту 6080 (noVNC) или 8765 (Foxglove Bridge)
3. Оператор получает графический доступ к ROS 2 стеку в браузере
4. Доступны: RViz2 (3D-визуализация), rqt_graph (граф узлов), rqt_console (логи), rqt_plot (графики), teleop (ручное управление)

### Health-метрики автономного режима

| Метрика | Описание | Доступна offline |
|---------|----------|-----------------|
| battery_level | Уровень заряда | Да (локальный watchdog) |
| gpu_temperature | Температура GPU Jetson | Да (tegrastats) |
| model_status | Статус каждой загруженной модели | Да (Health Monitor) |
| last_cloud_contact | Время последней связи с облаком | Да |
| buffer_usage | Заполненность буфера телеметрии | Да |
| task_status | Состояние текущей задачи | Да |
| ros2_node_status | Список активных ROS 2 узлов и их состояние | Да (ros2 node list, lifecycle) |

## Safety & Failsafe

### Аппаратный Emergency Stop

- Физическая кнопка на роботе — обесточивает моторы немедленно
- Не зависит от программного стека
- При активации — все контейнеры получают сигнал через GPIO/watchdog

### Программный Emergency Stop

- Safety Watchdog контейнер мониторирует критические параметры
- При обнаружении опасности: публикация /emergency_stop → все ROS 2 узлы останавливают движение
- Источники триггера: обнаружение человека в опасной зоне (Tiny YOLO + Pose Estimation), столкновение (bumper/IMU), потеря локализации, критическая температура GPU

### Watchdog-процессы

| Watchdog | Мониторирует | Действие при сбое |
|----------|-------------|-------------------|
| container_watchdog | Docker-контейнеры (healthcheck) | Перезапуск контейнера (restart policy: always) |
| ros2_lifecycle_watchdog | ROS 2 узлы (lifecycle state) | Перевод в inactive → повторная активация |
| gpu_watchdog | Температура и состояние GPU | Снижение NVPModel, выгрузка моделей |
| network_watchdog | MQTT-соединение, Wi-Fi signal | Переключение online/offline режима |
| battery_watchdog | Уровень заряда | Переключение энергопрофиля, возврат на базу |

### Ограничения движения

В автономном режиме при низкой уверенности сенсоров робот автоматически ограничивает:

- Максимальную скорость: 50% от номинальной
- Зону работы: только известные (картированные) области
- Действия манипулятора: запрещены без подтверждения модели с confidence > 0.9
- Приближение к людям: минимальная дистанция увеличивается с 0.5 м до 1.5 м
