# vLLM Service — Обзор

## Назначение

vLLM Service — микросервис для выполнения inference больших языковых моделей (LLM) и мультимодальных моделей. Обеспечивает понимание естественного языка, генерацию планов действий, анализ изображений с текстовым описанием и поддержку диалогового интерфейса.

---

## Зона ответственности

- Обработка текстовых запросов пользователей на естественном языке
- Генерация планов действий для роботов на основе текстовых команд
- Мультимодальный анализ: понимание изображений и видео с камер в контексте текстового запроса
- Поддержка Tool Calling для интеграции с Orchestrator
- Потоковая генерация ответов (streaming) для чат-интерфейса
- Суммаризация и объяснение результатов анализа сцены
- Доменная адаптация через LoRA-адаптеры без полного дообучения моделей

## Почему vLLM

### PagedAttention

vLLM использует механизм PagedAttention, который управляет KV-кэшем модели аналогично виртуальной памяти ОС. Это позволяет: эффективно использовать GPU-память (до 24x по сравнению с наивной реализацией), обслуживать больше одновременных запросов, динамически выделять и освобождать память KV-кэша.

### Continuous Batching

В отличие от статического батчинга, vLLM использует continuous batching: новые запросы добавляются в батч, как только в нём появляется свободное место (после завершения генерации для одного из запросов). Это минимизирует простой GPU и максимизирует throughput.

### OpenAI-совместимый API

vLLM предоставляет API, совместимый с OpenAI API, что упрощает интеграцию: стандартные клиенты (openai-python) работают без модификации, стандартные форматы запросов и ответов, поддержка streaming через Server-Sent Events (SSE).

## Архитектура внутренняя

### Компоненты

1. **API Server**: приём и маршрутизация запросов, валидация, управление потоками
2. **Tokenizer**: токенизация входных текстов и изображений (для мультимодальных моделей)
3. **Scheduler**: планирование выполнения запросов, управление приоритетами
4. **Engine**: ядро inference — выполнение forward pass модели
5. **KV Cache Manager**: управление памятью KV-кэша через PagedAttention
6. **Detokenizer**: преобразование выходных токенов обратно в текст

### Обработка запроса

1. Запрос поступает через API Server
2. Tokenizer конвертирует текст (и изображение, для мультимодальных) в токены
3. Scheduler помещает запрос в очередь с учётом приоритета
4. Engine выполняет генерацию токен за токеном
5. Каждый сгенерированный токен передаётся Detokenizer
6. Для streaming: каждый токен отправляется клиенту по SSE
7. Для non-streaming: полный ответ отправляется после завершения генерации

## Модели

### Стратегия выбора моделей

Платформа использует несколько моделей с различными специализациями:

- **Qwen2.5-7B-Instruct** — основная текстовая модель для планирования, reasoning, tool calling
- **LLaVA-1.6** — мультимодальная модель для детального анализа изображений с текстовым контекстом (требует GPU A100/A10G)
- **SmolVLM2-2.2B-Instruct** — компактная мультимодальная модель (2.2B параметров) для эффективного анализа изображений и видео, работает на GPU L4 и выше

Модели выбраны по критериям: достаточная производительность, хорошее следование инструкциям, поддержка Tool Calling (текстовая), возможность работы на доступных GPU, поддержка LoRA-адаптации для доменных задач. SmolVLM2 является предпочтительным вариантом для сценариев с ограниченными GPU-ресурсами или при необходимости анализа видео.

## Масштабирование

### Горизонтальное

- Несколько реплик vLLM за load balancer (на уровне Kubernetes Service)
- Каждая реплика обслуживает полную модель
- Load Balancer распределяет запросы по least-connections

### Вертикальное

- Tensor Parallelism: распределение одной модели по нескольким GPU (для моделей > 7B)
- Увеличение GPU-памяти для большего KV-кэша и concurrent requests

### Целевые показатели

| Параметр | Значение |
|----------|---------|
| Time-to-First-Token (p95) | < 500 мс |
| Tokens/sec (streaming) | > 30 tok/s |
| Concurrent requests | > 20 |
| GPU utilization | 70–85% |
| Доступность | 99.9% |

## Обработка ошибок

| Ситуация | Действие |
|----------|----------|
| Превышение max_tokens | Генерация останавливается, возвращается partial result с флагом truncated |
| OOM (нехватка GPU-памяти) | Preemption — низкоприоритетный запрос вытесняется, его KV-кэш сохраняется на CPU для возобновления |
| Timeout (> 60 сек) | Запрос отменяется, клиенту возвращается ошибка timeout |
| Некорректный формат ввода | Возвращается ошибка валидации с описанием |
| Модель не загружена | Возвращается 503 Service Unavailable, retry через 5 секунд |

## LoRA-адаптеры

### Назначение

vLLM поддерживает динамическую загрузку LoRA-адаптеров (Low-Rank Adaptation), что позволяет адаптировать базовые модели к доменным задачам без полного дообучения. Это критично для платформы AgentsSwarm, где требуется специализация моделей под конкретные типы роботов, объектов и сценариев использования.

### Ключевые возможности

| Параметр | Значение |
|----------|---------|
| Максимальный ранг LoRA | 64 |
| Одновременных адаптеров | До 4 |
| Совместимость с квантизацией | AWQ, GPTQ, BitsAndBytes |
| Загрузка адаптеров | HuggingFace Hub или локальный путь |
| Применение | Per-request (разные адаптеры для разных запросов) |

### Сценарии использования в платформе

- **Доменная адаптация текстовой модели**: LoRA-адаптер, обученный на инструкциях для робототехнических задач, улучшает качество планирования
- **Специализация мультимодальной модели**: адаптер, обученный на изображениях складских объектов, повышает точность описания сцен
- **Мультиязычная адаптация**: разные адаптеры для русского и английского контента
- **A/B тестирование**: одновременная работа нескольких адаптеров для сравнения качества

### Совместная работа с квантизацией (QLoRA)

vLLM поддерживает паттерн QLoRA — комбинацию квантизированной базовой модели с LoRA-адаптерами. Базовая модель загружается в квантизированном виде (BitsAndBytes, AWQ или GPTQ), а LoRA-адаптер применяется поверх неё в полной точности. Это позволяет получить качество, близкое к полноточной дообученной модели, при значительно меньшем расходе GPU-памяти.
