## 2. Реализованные методы ускорения

В ходе работы были протестированы три основных метода оптимизации, интегрированных в пайплайн обучения:

### 2.1 Knowledge Distillation (KD)
*   **Описание**: Обучение компактной модели Student под руководством полноразмерной модели Teacher.
*   **Механизм**: Использование комбинированной функции потерь (Distillation Loss + Task Loss).
*   **Результат**: Создана архитектура, превосходящая базовую по параметрам в 443 раза за счет уменьшения количества слоев трансформера и проекционных размерностей.

### 2.2 INT8 Quantization (Анализ)
*   **Описание**: Подготовка модели к переходу с FP32 на 8-битные целые числа.
*   **Анализ**: Скрипт `OptimizationManager` выявил 5 квантуемых слоев из 27 (коэффициент применимости 18.5%). Это связано с тем, что основные веса VLM энкодера заморожены или требуют специфической обработки.
*   **Потенциал**: Уменьшение размера модели в 4 раза и ускорение инференса на CPU/Edge устройствах.

### 2.3 Structured Pruning
*   **Описание**: Структурное удаление весов для разреживания модели.
*   **Результат**: Применение прунинга позволяет дополнительно снизить вычислительную нагрузку на Linear слои, что критично для работы в реальном времени.

## 3. Алгоритм применения методов

Пайплайн экспериментов реализован в `src/scripts/experiments/hw2/run_experiment.py` и следует следующей логике:

1.  **Инициализация**: Загрузка Teacher-модели и конфигурация Student-модели.
2.  **Дистилляция**: Запуск цикла обучения (1 эпоха для теста, целевое — 20+) с расчетом MAE для каждой компоненты действия.
3.  **Оптимизация**: Применение `OptimizationManager` для оценки возможности квантования и прунинга.
4.  **Валидация**: Оценка `Val Loss` и `MAE` после каждого этапа.

## 5. Инженерные выводы

1.  **Экстремальное сжатие**: Достигнуто сжатие >400x за счет того, что Student модель фокусируется только на решающей части (Action Head и адаптеры), в то время как Teacher содержит огромный объем общих визуально-языковых знаний.
2.  **Эффективность KD**: Дистилляция является наиболее мощным инструментом в данном проекте, позволяя радикально уменьшить объем вычислений.
3.  **Комплексный подход**: Для достижения целевой задержки <100ms на Edge-устройствах необходимо комбинировать KD с квантованием, так как одно лишь уменьшение параметров не гарантирует оптимального использования кэша процессора.
